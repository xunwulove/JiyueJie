# 手机横屏尺寸适配核查报告

> 核查日期：2026-10-12
> 项目：极悦界（MusicFree RN 0.76.5 fork）
> 开发根：`E:\xunwu\MusicFreeApp\MusicFree`
> 核查范围：手机横屏模式下的组件重叠问题、rpx/dp 尺寸体系合格性、QQ音乐/网易云音乐对照

---

## 一、问题背景

用户在手机横屏模式下使用时发现组件出现重叠现象（竖屏正常）。经核查，手机横屏时屏幕宽度 ≥ 600dp，触发 `useIsTablet() = true`，走平板布局分支（左侧播放区 30% + 右侧内容区 70%），但此时屏幕高度仅约 360–420dp，远小于真实平板（iPad 横屏高度 ≥ 768dp），导致平板布局中按高屏设计的固定尺寸组件在矮屏上溢出重叠。

---

## 二、根因分析

### 2.1 判断逻辑缺陷（主因）

**文件**：`src/utils/tablet.ts:5`

```typescript
export function isTabletScreen(): boolean {
    return Dimensions.get("window").width >= 600;
}
```

- 仅以**宽度 ≥ 600dp** 为判据，不考虑高度。
- 典型手机横屏尺寸：iPhone 12 Pro 横屏 844×390dp、Pixel 7 横屏 915×412dp——宽度均远超 600，但高度仅 ~390–412dp。
- `useIsTablet`（`src/hooks/useIsTablet.ts`）监听 Dimensions change，旋转后自动重算，因此横屏瞬间切换到平板布局。
- **代码没有区分"真平板"（高 ≥ 700dp）和"手机横屏"（高 ~390dp）**。

### 2.2 布局结构缺陷

平板布局为"左 30% 播放区 + 右 70% 内容区"（`src/pages/home/index.tsx:243-248`）。左播放区 `TabletPanel` 内部使用大量**固定 dp 高度**，这些值按真平板高度（≥700dp）设计，在 ~390dp 矮屏上垂直方向必然溢出。

### 2.3 rpx 不是问题

`src/utils/rpx.ts:9`：

```typescript
return (rpx / 750) * minWindowEdge;
```

rpx 基于 `minWindowEdge`（横屏时 = 短边 ~390dp），横屏时自动缩小，不会放大。问题全部来自固定 dp 值和平板分栏结构本身。

## 三、重叠组件清单（按严重程度排序）

### 🔴 高严重度

#### 3.1 TabletPanel 封面固定 200dp — 垂直溢出/挤压

- **文件**：`src/pages/home/components/tabletPanel.tsx:371-372`
- **组件**：`cover`（专辑封面 FastImage）
- **当前值**：`width: 200, height: 200, marginBottom: 16`（固定 dp）
- **横屏实际表现**：
  - 左面板总高 ≈ 390dp（iPhone 12 Pro 横屏）
  - 固定占用：header 56 + marginBottom 16 = 72dp；bottom 区 padding 24 + slider 28 + gap 4 + controlBar 52 = 108dp；container paddingBottom 16dp
  - 固定合计 ≈ 196dp
  - `playContent`（flex:1）可用高度 = 390 - 196 = **194dp**
  - 但封面单独占 200 + 16 = **216dp**，已超出整个 playContent
- **后果**：封面溢出 flex 容器，歌词弹性区（`lyricPlaceholder: flex:1`）被压缩至接近 0，歌名/歌手文字与底部进度条/控制栏发生垂直重叠。

#### 3.2 Panel 弹出层覆盖顶部 Tab 栏

- **文件**：`src/components/panels/base/panelBase.tsx:193`
- **组件**：`panelBody`（底部弹层 Animated.View）
- **当前值**：平板分支仅传 `{ left: "30%", width: "70%" }`，**未传 `top: TAB_BAR_HEIGHT(56)`**
- **横屏实际表现**：
  - 遮罩层 `maskWrapper` 正确使用了 `style.tabletBound`（含 `top: 56`，见 line 259-263）
  - 但面板本体 `panelBody`（line 191-206）在 horizontal 分支拿到的是 `height: vh(100) - safeAreaInsets.top, bottom: 0`（line 195-196）
  - 横屏 safeAreaInsets.top ≈ 0 → 面板从 top:0 延伸到底部，**顶部 56dp 覆盖了 TabBar**
- **后果**：弹出播放列表/输入面板时，面板顶部遮挡"首页/搜索/音乐库/我的"Tab 栏。

#### 3.3 统计页左右分栏在矮屏上日历区被压扁

- **文件**：`src/pages/statistics/index.tsx:468-475`
- **组件**：`splitRow`（排行左 50% + 日历右 50%）
- **当前值**：`flexDirection: "row"`，日历卡片 `onLayout` 实测高度驱动 TOP N 行数
- **横屏实际表现**：
  - 右内容区可用高 ≈ 390 - 56(TabBar) = 334dp
  - AppBar(~44) + chips(~40) + overview 卡(minHeight 110) + margins(~30) ≈ 224dp
  - `splitRow` 仅剩 **~110dp** 高度
  - 日历卡 padding(24) + header(~20) + weekRow(~20) = 64dp，剩余 ~46dp 仅够 **1~1.5 行日历格子**（正常需 5~6 行）
  - 排行列 `flex:1` 跟随 calendarHeight(~110dp)，`topCount = floor((110-28)/44) = 1`，被 clamp 到最小 3 行（`RANK_ROW_H=44`），3×44=132dp > 110dp，**排行行溢出**
- **后果**：日历热力图几乎不可见，排行行溢出容器底部。

### 🟡 中严重度

#### 3.4 首页首屏内容过高，推荐区被挤出可视区

- **文件**：`src/pages/home/components/homeBody/statsRow.tsx:221` + `operations.tsx:223`
- **组件**：StatsRow 三卡 + Operations 四入口
- **当前值**：平板分支 `minHeight: 110`（statsRow）和 `minHeight: 96`（operations）
- **横屏实际表现**：
  - StatsRow：marginTop 20 + minHeight 110 + marginBottom 20 = **150dp**
  - Operations：marginVertical 20×2 + minHeight 96 = **136dp**
  - 合计 286dp，右内容区可用 334dp，仅剩 ~48dp 给 RecommendSection 标题
- **后果**：推荐歌单横滑区完全在首屏下方，用户需滚动才能看到（不算重叠，但首屏体验差）。

#### 3.5 全屏播放页播放按钮 80dp 在矮屏上过大

- **文件**：`src/pages/musicDetail/components/bottom/playControl.tsx:28`
- **组件**：`playBtn`（圆形播放/暂停按钮）
- **当前值**：`playBtnSize = isTablet ? 80 : 56`（横屏时取 80dp）
- **横屏实际表现**：
  - 全屏播放页横屏走 `leftPane(6) + rightPane(4)` 分栏
  - leftPane 固定高度：NavBar(~44) + titleBlock(~70) + Bottom(SeekBar 28 + PlayControl 80 + padding 8) ≈ 230dp
  - 歌词区（flex:1）≈ 160dp——勉强可用
- **后果**：80dp 播放钮占屏幕高度 20%，视觉比例失调；rightPane 封面 `horizontalWrapper: width 88%, aspectRatio:1`，在 40% 宽度(~337dp)下封面高 ~296dp，接近溢出边缘。

## 六、QQ音乐 / 网易云音乐尺寸策略对照

### 6.1 重要前提：反编译包为车机/IoT 版

| 包名 | 实际版本 | 说明 |
|------|---------|------|
| `com.tencent.qqmusiccar` | QQ音乐**车机版** | dimens 中大量 `*_grandland_*` 命名，佐证腾讯 Grandland 车机平台 |
| `com.netease.cloudmusic.iot` | 网易云**IoT/车机版** | 面向 IoT 设备（车机/音箱） |

它们的"横屏"是车机抬头屏**本身固定横屏**，不是手机旋转横屏适配。因此对照结论需结合此前提理解。

> 反编译产物中无 `AndroidManifest.xml`，`screenOrientation` / `supports-screens` 无法直接验证，以下结论基于资源策略反推。

### 6.2 两包适配策略对照

| 维度 | QQ 车机版 | 网易云 IoT 版 |
|------|----------|--------------|
| 业务横屏专属布局（`layout-land`） | **0 个**（3 个 land 布局全是 Material 库时间选择器） | **1 个**（混淆名 `e9`，疑似库） |
| 业务 sw600dp 专属布局 | **0 个**（2 个都是 snackbar 库） | **0 个** |
| 业务 dimens 带 land/sw600dp 覆盖 | **无** | **无** |
| 平板判断开关 | `bool/is_tablet = (sw600dp) true` | 无 |
| 业务尺寸单位 | dp（控件）+ sp（文字），一套走天下 | 同 |
| 自有 dimens 典型值 | 7.5sp、8sp、10dp 等（车机大屏低密度 UI） | 资源名混淆，策略相同 |

**所有带 `(land)`/`(sw600dp)`/`(large)`/`(xlarge)` 限定符的 dimens，经资源名核对全部来自 AndroidX 库**（`abc_action_bar_*`、`material_time_picker_*`、`mr_controller_*`、`mtrl_alert_dialog_*`），业务 dimens 零覆盖。

### 6.3 对我方的启示

1. **这两家的策略是"从一开始就为固定横屏设计一套布局"**，而不是"竖屏布局 + 横屏分支"。它们不为 land 单独写布局和 dimens，一套 dp/sp 固定尺寸适配固定横屏设备。
2. 如果我方定位为车机/平板/电视类固定横屏设备：可以学这两家——一套默认布局 + dp/sp 固定尺寸 + 用 `bool/is_tablet` 做程序化分支。
3. 如果我方是手机 App 想支持横屏：**这两个包没有提供可借鉴的手机横屏模式**。主流手机音乐 App（QQ音乐手机版、网易云手机版）通常**锁定竖屏**，不支持横屏。如需对照，应反编译手机版（`com.tencent.qqmusic` / `com.netease.cloudmusic`）并读取其 `AndroidManifest.xml` 的 `screenOrientation`。
4. 横屏宽度变化应交给 `flex`/`weight`/比例布局吸收，不要给每个组件写两套 dp 值。

## 七、合格判定

| 模块 | 判定 | 说明 |
|------|------|------|
| 平板布局框架（左 30% + 右 70%） | ⚠️ 不合格 | 分栏结构本身合理，但未适配矮屏 |
| TabletPanel 左播放区 | 🔴 不合格 | 封面 200dp 固定高度在 390dp 屏上必然溢出 |
| Panel/Dialog 浮窗定位 | 🔴 不合格 | 面板本体缺 `top:56`，覆盖 Tab 栏 |
| 统计页分栏 | 🔴 不合格 | 日历+排行并排需 ~400dp 高，横屏仅 110dp |
| 首页内容区（ScrollView） | 🟡 勉强合格 | 可滚动，但首屏被 statsRow+operations 占满 |
| 音乐库 Tab | ✅ 合格 | 头部卡片 + FlatList flex:1，列表可滚动 |
| 我的 Tab（ScrollView） | ✅ 合格 | 内容可滚动，卡片 minHeight 在首屏内 |
| 全屏播放页（横屏分栏） | 🟡 勉强合格 | 歌词区~160dp 可用，但 80dp 播放钮过大 |
| 底部音乐栏 | ✅ 合格 | 平板模式下完全隐藏（`!isTablet &&`） |
| VerticalSafeAreaView | ✅ 合格 | 平板时 edges 仅 bottom，避免双重 safe area |
| rpx 体系 | ✅ 合格 | 基于短边，横屏自动缩小，无放大问题 |
| useIsTablet 判断逻辑 | 🔴 不合格 | 仅看宽度不看高度，无法区分真平板和手机横屏 |

### 总体判定：**不合格**

核心问题是 `useIsTablet()` 只看宽度不看高度，导致手机横屏（844×390）误走平板布局，而 TabletPanel 的 200dp 固定封面 + 56dp header + 108dp 控制栏 ≈ 364dp 固定高度，在 390dp 矮屏上几乎占满全部垂直空间，歌词区和内容必然挤压重叠。

## 八、修复建议（落到文件+改动点）

### P0 — 必须修复

#### 1. `src/pages/home/components/tabletPanel.tsx` — 封面自适应

- **改动点**：line 371-372，封面 `width: 200, height: 200` 不应固定。
- **建议**：根据可用高度动态计算封面尺寸：
  ```typescript
  const coverSize = Dimensions.get("window").height < 500 ? 130 : 200;
  ```
  或改用 `aspectRatio: 1` + `maxHeight` 约束，让封面在 flex 容器内自适应。

#### 2. `src/components/panels/base/panelBase.tsx` — 面板 top 偏移

- **改动点**：line 193，平板分支 `{ left: "30%", width: "70%" }` 缺少 `top`。
- **建议**：改为 `{ left: "30%", width: "70%", top: TAB_BAR_HEIGHT, bottom: 0 }`，并在 horizontal 分支判断 `!isTablet` 才使用 `height: vh(100) - safeAreaInsets.top`。

### P1 — 建议修复

#### 3. `src/pages/statistics/index.tsx` — 分栏退化

- **改动点**：line 468-475，平板左右分栏在矮屏时应退化为上下排列。
- **建议**：分栏条件改为 `isTablet && Dimensions.get("window").height >= 500`，矮屏时走手机分支（日历在上、排行在下，可滚动）。

#### 4. `src/pages/musicDetail/components/bottom/playControl.tsx` — 播放钮尺寸

- **改动点**：line 28，`playBtnSize = isTablet ? 80 : 56`。
- **建议**：增加高度判断：`Dimensions.get("window").height < 500 ? 56 : (isTablet ? 80 : 56)`。

#### 5. `src/pages/home/components/homeBody/statsRow.tsx` + `operations.tsx` — 卡片高度

- **改动点**：statsRow line 221 `minHeight: 110`，operations line 223 `minHeight: 96`。
- **建议**：矮屏时缩小至 ~70–80dp，或将整个 HomeBody 在矮屏时改为手机布局（竖排卡片）。

### P2 — 优化项

#### 6. `src/hooks/useIsTablet.ts` + `src/utils/tablet.ts` — 增加"真平板"判断

- **改动点**：增加高度维度。
- **建议**：导出 `isLargeScreen()` = `width >= 600 && height >= 500`，让矮屏横屏手机走紧凑布局分支而非完整平板布局。或新增 `useIsRealTablet()` hook。

#### 7. `src/pages/home/components/tabletPanel.tsx:102` — 问候语字号

- **改动点**：`fontSize: 32` 在 56dp header 中偏大。
- **建议**：矮屏时改为 `fontSize: 20~24`。

### 策略级建议

**方案 A（推荐）：锁定手机竖屏**
- 参考主流手机音乐 App 做法，在 `AndroidManifest.xml` 中锁定 `screenOrientation="portrait"`，手机端不支持横屏。
- 平板/车机等大屏设备仍可横屏（这些设备高度充足，平板布局正常）。
- 改动最小，风险最低，与 QQ音乐/网易云手机版策略一致。

**方案 B：手机横屏走紧凑平板布局**
- 保留横屏支持，但 `useIsTablet` 增加高度判断（`width >= 600 && height >= 500`）。
- 矮屏横屏（手机）走"紧凑平板布局"：封面缩小、控制栏压缩、统计页退化为竖排。
- 工作量大，需逐页适配矮屏。

**方案 C：手机横屏走手机布局**
- `useIsTablet` 判断改为基于设备类型（`react-native-device-info` 的 `isTablet()`）而非屏幕尺寸。
- 手机无论横竖都走手机布局，平板无论横竖都走平板布局。
- 最符合用户直觉，但需确认 `react-native-device-info` 的 `isTablet()` 在折叠屏/小平板上的准确性。
