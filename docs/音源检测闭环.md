## 二、环节一：音源来源

音源（洛雪 LX / MusicFree MF 两类格式）来自**订阅站聚合 + 开源源仓库**两路：

| 来源 | 说明 | 典型地址 |
|---|---|---|
| 订阅站聚合 | 音乐Free插件Hub 聚合器 + onemusic/moro 订阅站，HTTP 200 + ≥1KB + 特征词筛选 | — |
| 洛雪 LX 源仓库（需转 MF） | `pdone/lx-music-source` | `raw.githubusercontent.com/pdone/lx-music-source/main/{sixyin,lx,huibq,flower}/latest.js`——**极悦界 App 不支持 LX 格式**，仅作转 MusicFree 前的源素材 |
| MusicFree 插件 | 各作者维护 | `ThomasBy2025/musicfree`、`maotoumao/MusicFreePlugins`、`kevinr/tvbox` 等（gitee 直连 / github 走国内镜像） |

> ⚠️ **极悦界 App 只支持 MusicFree 格式插件**（`src/core/pluginManager` 加载 MF 插件，无洛雪 LX 引擎）。洛雪 LX 源需先转成 MF 格式（`mf_*` 转换版）才能被 App 使用；`verify_lx.cjs` 验证的是洛雪宿主下的 LX 源本身，**不代表 App 可直接用**。
>
> 当前订阅清单：`sources/plugins.json` = **30 源 A 类筛选**（2026-10-23，来源=插件Hub 聚合器 + onemusic/moro），与 gitee `jiyuejie/sources/plugins.json` 逐字节一致。历史探测产物见 `docs/archive/音源清单-20261022/`（50 源精选，已归档，非当前清单）。
>
> ⚠️ **三份清单层级不同，勿混淆**（2026-10-25 核对确认）：
> 1. `sources/plugins.json`（30 源）= **正式清单**：A 档（可搜+可播）最终发布物，App 更新订阅拉取的就是它；
> 2. `tools/source-probe/plugins.json` / `plugins_verify.json`（各 97 源）= **探测候选池**：探测 App 装机实测的对象（含未过审/待复核源），从候选池里筛出 A 档进正式清单；
> 3. `tools/verify_sources/verify_downloads.cjs` 的 `INDEX`（9 源：4 LX + 5 MF）= **开发期抽查样本**：只验开发中/变更中的源，非全量。

## 三、环节二：验证（电脑脚本）

`tools/verify_sources/` 为当前主验证工具（Node vm 模拟宿主，无需装机）。三步递进：

| 脚本 | 验证内容 | 说明 |
|---|---|---|
| **verify_downloads.cjs** | 第一步：索引 URL 可下载性 + JS 语法检查 | 逐个下载音源脚本（github 优先国内镜像 ghproxy.net / gh-proxy.com，与 App 逻辑一致）；`node --check` 验语法；输入源清单内嵌在脚本 `INDEX` |
| **verify_lx.cjs** | 洛雪 LX 源执行验证（**非 App 直接支持**） | 沙箱加载 LX 源 → 注入洛雪宿主（lx/env/md5 纯 JS）→ 搜索「周杰伦」→ 取 320k 链接 → HTTP 探测。仅用于「LX 源转 MF 前判断源本身可用」，转成 MF 格式后才被 App 使用 |
| **verify_mf.cjs** | MusicFree 插件执行验证 | 沙箱加载插件（兼容 `exports.default` / `__musicFreeCore__`）→ 搜索 → 取链接；单源隔离 + 超时 |

运行：
```bash
cd E:\xunwu\deepseek\jiyuejie\tools\verify_sources
node verify_downloads.cjs   # 先验下载/语法
node verify_mf.cjs          # MusicFree 源执行验证
node verify_lx.cjs          # 洛雪 LX 源执行验证
```
> 音源脚本存 `dl2/`（LX 源 4 个 + MF 源 5 个副本）；`node_modules/` 为 vm 运行依赖。

**增强工具（历史，更全但位于项目外）**：`E:\Temp\Deepseek\source-check\probe_plugin.js`（v3）——AI 初筛 → 真实探测 → **人工复核** → 一键发布 完整工作流，含：
- 深度播放验证（`--play=N`，解析真实播放地址 + GET Range 首块探测，防假阳性：Content-Type 必须为音频类）
- 档位判定：**A**（可搜+可播）/ **A1**（可搜+防盗链403需复核）/ **B1**（可搜取不到地址）/ **B2**（取到但探测失败）/ **B**（可搜未验播）/ **C**（仅可达未搜到）/ **X**（失效）
- 歌单能力验证（`--sheets`）、多关键词（`--keywords`）、AI 候选入口（`--from`）、一键发布清单（`--publish`，只收 A 档）、定时监控（`--interval`）、插件源码缓存（`--cacheDir`）
- 用法详见 `docs/archive/音源清单-20261022/探测工具使用说明.md`

## 四、环节三：验证（真机）

| 手段 | 工具 | 说明 |
|---|---|---|
| 独立探测 App | `tools/source-probe/`（RN 工程，打包「音源探测 v0.1.x」APK） | **装机实测**：真实 QuickJS 引擎跑插件，判"可播"；内置 plugins.json 作为探测清单 |
| App 内探测 | `src/core/probeService.ts`（probeSingle） | 软件内"检测音源"按钮：逐源探测**搜索/解析/播放/歌词/歌单**五维（2026-10-25 补全歌词与歌单维度）；**2026-10-24 起探测运行互斥**（整轮锁，防并发），手动/自动探测在跑时再次点击提示"音源检测进行中"，不启动第二轮；串行 + 源间 1.5s，**总预算 120s**（2026-10-25 由 60s 放宽），单步均有超时保护（歌词 5s / 歌单各段 8s），失败不重试 |

> 真机判定是最终口径：电脑脚本能快速判"可搜+可取链+可下载"，但**能否真正播放以 App 内听感为准**（防盗链/临时签名/地区限制脚本无法完全模拟）。

## 五、环节四：探测维度与结果处理

### 探测维度（7 维）

| # | 维度 | 探测内容 | 判据 |
|---|---|---|---|
| ① | 可下载/可加载 | URL 可达、脚本可下载、JS 语法有效、沙箱能加载执行 | 失败 → X |
| ② | 搜索能力 | 能否搜到歌（多关键词任一命中，规避单词盲区） | 空 → C |
| ③ | 播放取链 | 能否解析真实播放地址（歌自带 url → `getMusicUrl` → `getMediaSource`） | 取不到 → B1 |
| ④ | 地址可访问性 | HTTP 200/206 且 Content-Type 为音频类（防假阳性：403=防盗链、HTML/JSON 错误页=不可播） | 403→A1 / 失败→B2 |
| ⑤ | 歌单能力 | 推荐歌单/用户歌单/榜单能否拉到非空列表（对应 App 推荐歌单功能） | 达标/否 |
| ⑥ | 登录类标记 | 插件含 login/verifyToken → 标注"需登录" | 标记 |
| ⑦ | 可用率（App 内） | probeService 逐源探测统计，音源管理按可用率降序 | 0~1 |

### App 内探测维度（probeService，2026-10-25 补全）

软件内"检测音源"逐源探测 **5 维**（仅对具备对应能力的源探测；不具备则该维度不记录、不误伤）：

| 维度 | 探测内容 | 记录位置 | 判据 |
|---|---|---|---|
| 搜索 | `search("海阔天空",1,"music")` | 合成可用率（权重 10%） | 有结果 |
| 解析 | `getMediaSource` 按音质序取链 | 合成可用率（权重 30%） | 有播放地址 |
| 播放 | 深度模式静音 ExoPlayer ≥2s（音量 0、不抢焦点、不打断当前播放） | 合成可用率（权重 60%） | 播放位置推进无错 |
| 歌词 | `getLyric`（搜索结果第 1 首，5s 超时） | 歌词可用率（独立） | 返回 rawLrc/trans 非空 |
| 歌单 | `getRecommendSheetTags`（8s）→ 真实歌单/标签 → `getMusicSheetInfo`（8s）拉歌曲 → 歌单第 1 首解析（深度再静音可播） | **推荐歌单可用率（独立 recommend 统计）** | **歌单能显示（列表非空）+ 内容可播（第一首有地址/可播）** |

> 歌单维度**独立于合成可用率**：歌单显示有问题但播放路径正常的源，不会被歌单维度拖累合成可用率（用户 2026-10-25 明确要求）。自动探测（轻量，每日一轮）做搜索/解析/歌词/歌单显示，不做播放；手动"检测音源"全量深度（含播放）。**自动探测按维度过滤 + 维度级执行**（2026-10-25）：只探测 search/parse/lyric/sheet 中**缺失或 >24h 未探测的维度**，已验维度不重跑（单维失败/超时不会拖累其他维度重跑）；play 维度只由手动深度维护。**真实播放成功会刷新该源 play 维度探测时间戳**（播放过即证明可播，24h 内不再重复探测播放功能；播放失败不刷新，留给探测核实）——其余维度（搜索/歌词/歌单）只由探测本身刷新，用户使用行为不豁免。
>
> **播放退化（可播→仅可搜）的发现机制**（2026-10-25 核对确认）：自动探测不做播放，退化不靠自动轮发现——兜底是①**用户实际播放失败会记 `recordPlayResult(false)` 进 play 维度**（可用率下降 → 排序下沉 → 音源管理可见）；②手动"检测音源"深度探测刷新 play 维度。

### 结果处理（档位 → 动作）

| 档位 | 含义 | 处理 |
|---|---|---|
| **A** | 可搜 + 可播 | **入正式清单**（`--publish` 只收 A 档） |
| **A1** | 可搜 + 防盗链 403 | **人工复核**：App 内点播确认，通过可手动补入 |
| **B1** | 可搜但取不到地址 | **人工复核**（可能需登录/参数/特定音质） |
| **B2** | 取到地址但探测失败 | **人工复核**（4xx/5xx/超时/非音频 200） |
| **B** | 可搜未验播（`--play=0`） | 视需要重跑播放验证 |
| **C** | 仅可达未搜到（限流重试后仍空） | 不入选，观察/换源 |
| **X** | 失效（下载/加载失败/无搜索接口） | **下架/排除** |
| 需登录 | 含 login/verifyToken | 标注，App 内复核能否免登录使用 |

> 定时监控（probe_plugin.js `--interval`）对比每轮，输出：新增失效 / 恢复可用 / 升级可播 / 可播→仅可搜 / 新增 / 移除。

### 探测报告（report.ts v2，2026-10-25 改进）

探测软件报告（Markdown，可分享投喂 AI 二次整理）升级内容：

- **五档分类**（按用户价值）：🟢 **全通**（真能播放）/ 🟠 **可解析不可播**（半死源，可修复）/ 🟡 **半可用**（部分能力可用）/ 🟣 **歌单型源**（搜索无结果属正常，非失效）/ 🔴 **死源**（全能力失败）
- **"可解析不可播"单独成节**：能搜索、能取链但真实播放失败——**不是死源**，按失败原因处置并附**建议动作**列：403/鉴权→补 headers/Referer；404→直链失效；网络/超时/缓冲→接口不稳定或直链时效短（播放时动态取链）；格式不支持→URL 实际格式与插件声明不符
- **全部明细全字段**：每个音源一行展示——5 类搜索逐个 ✓/✗（单曲/专辑/歌手/歌单/歌词）+ 解析/播放/歌单/歌词/翻译/歌手作品/专辑/评论 + 样本歌曲 + 失败原因 + 耗时
- **失败原因标准化**：`classifyPlayError` 归一（403/404/网络/格式/鉴权等）后聚合统计，替代原始报错字符串
- **播放验证静音**（playback.ts）：深度播放验证 `setVolume(0)`——验证只依赖缓冲/解码/状态机（进入 Playing + 持续 ≥2s 无错），与音量无关，探测过程**不出声**

## 六、环节五：产出 plugins.json

- **A 档**（可搜+可播）进正式清单；**A1/B1/B2 留人工复核**，复核通过可手动补入。
- **gitee 严格格式**：顶层仅 `desc` + `plugins`；条目仅 `name/version/url` 三字段；缺 version 补 `1.0.0`；不加其它字段。
- desc 注明实测日期、可播数量与关键词。
- 当前正式清单：`sources/plugins.json`（30 源 A 类，含 desc/plugins）。

## 七、环节六：发布（gitee）

音源随软件同仓托管于 **gitee `xunwulove/jiyuejie`**，路径 `sources/plugins.json`：

1. **GET** `https://gitee.com/api/v5/repos/xunwulove/jiyuejie/contents/sources/plugins.json` 拿当前 `sha`；
2. **PUT** 同接口，`content` 为 **base64** 编码的新 plugins.json，带 `sha`（Gitee contents 接口必带 base64，传明文会被静默存成乱码）；
3. **验证**：`curl -L` 直链 200 + 内容一致：
   - 主链 `https://gitee.com/xunwulove/jiyuejie/raw/master/sources/plugins.json`
   - 备用 CDN `https://raw.giteeusercontent.com/xunwulove/jiyuejie/raw/master/sources/plugins.json`

## 十、日常维护建议

1. 新增/更换音源：先用 `verify_downloads.cjs` 确认可下载可加载 → `verify_mf.cjs`/`verify_lx.cjs` 确认可搜可取链 → 装机（探测 App 或 App 内检测）确认真实可播 → 只有 A 档入 `sources/plugins.json`。
2. 发布走 gitee contents PUT（base64 + sha），发完验证直链。
3. 定期用 probe_plugin.js 定时监控（`--interval`）发现失效源，及时下架/换源。
4. 音源脚本若大量更新，同步刷新 `tools/verify_sources/dl2/` 副本。
