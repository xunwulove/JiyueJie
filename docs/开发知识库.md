### 1.1 项目是什么

**极悦界** = MusicFree（maotoumao 开源项目）的本地 fork，**个人自用、不分发**。定位：

- **内核**：完整保留 MusicFree 插件化体系——音源引擎支持 QuickJS 与 WebView 双执行环境，可安装洛雪/MusicFree 格式音源插件（订阅源如 `qwerwhr/musicfree-plugins`）；
- **UI**：全面迁移对齐旧项目 APlayer（盐音）风格：平板左右分栏（左播放区 30% / 右内容区 70%）、一级/二级/三级页面层级规范、卡片/渐变/字体档位体系；
- **增强功能**：软件内下载更新（gitee 更新链路）、WebDAV 备份、推荐歌单/排行榜（官方两级结构 + 独立可用率择优 + 每日缓存防封禁）、扫描设置页（媒体库/自定义文件夹/屏蔽目录/60 秒过滤）、三处歌词卡拉OK进度染色 + 边缘渐隐、白天背景微渐变 + 播放封面氛围取色、品牌视觉（启动页/图标，见 `brand-assets/`）。

旧项目 APlayer 位于 `E:\xunwu\Deepseek\APlayer`（保留不动，作 UI 参照源）；本 fork 工作目录 = `E:\xunwu\Deepseek\jiyuejie`。

### 1.6 硬性规范速查

1. **导航层级**：一级=顶端 tab 切换（内容区唯一入口）；二级=右内容区**从右滑入的覆盖层**（不覆盖 tab 栏、不覆盖左播放区）；三级=浮窗；**三级即最底层**（迫不得已再弹仍守三级规范）；**全屏播放页 = 唯一覆盖全屏的操作**（点击左播放区进入）。
2. **平板三级浮窗**：中心 = 右内容区中心（**不含 tab 栏**）；宽 = 内容区 60%（手机 86%）；最大高 = 内容区 70%（超长内部滚动）；标题行 52dp 品牌渐变 + 4×20dp 胶囊竖条；底部按钮行**同高 52dp、同渐变**；正文 13sp/行高 21；按钮 14sp Medium。**任何弹窗的确定/取消按钮不得随内容滚动**。
3. **返回层级**：全屏播放层 → 覆盖层栈（逐级）→ 一级页 → 退出；搜索页返回回上一层级；任何界面点 tab → 清空覆盖层栈并切到对应一级页（`switchTab`）。
4. **卡片规范**：2/3/4 卡平均分布占满内容区一行，圆角 14/16/18（按卡型），渐变卡 primary α0.14→0.03，按比例卡有放大；我的页平板=左右两大卡。
5. **字体档位**（`src/constants/uiConst.ts`）：tag10 / caption11 / description12 / normal13 / subTitle14 / body15 / content16 / title18 / large22 / appbar18。列表行标题 = **body15 Medium**；菜单/弹窗选项行 = 16；Dialog 正文 13/21；**禁止 rpx 字号魔法值**（字号随屏放大违规）。
6. **图标档位**（iconSizeConst）：small16 / light20 / normal24 / big32 / large40。
7. **平板判断**：统一走 `isTabletScreen()` / `useIsTablet()`（600dp 分界），**禁止新写裸 `Dimensions.get("window").width` 判断**。
8. **状态栏**：`StatusBar` 默认跟随主题（白天 dark-content）；二级页弹出不覆盖、不改色。
9. **播放区/内容区**：平板左 30% 播放区**严禁任何界面内容遮挡**（二级/三级都在右内容区内）；顶部品牌图标与问候语与内容区 tab 同层次。
10. **列表行基座**（`components/base/listItem.tsx`）：heightType big64 / normal56 / small48 / smallest36；paddingH 16；封面 48dp 圆角 8。新增行组件一律复用基座，不另起炉灶。
11. **沉浸歌词层**：仅**播放中** 15s 无操作进入（暂停不计时、有操作重置、切歌重计）；退出回全屏页；沉浸页只能从全屏页进入（左侧播放区同层复用）。
12. **三处歌词区（全屏/沉浸/左侧）**：统一 FlatList 滚动 + 边缘渐隐（平板 160/手机 120，左侧 120）+ 卡拉OK逐字染色（karaokeText.tsx）；沉浸页歌词区下端与右封面下端精确齐平（`lyricWrapTablet paddingBottom:64`，**勿在 leftPane 重复加**）。
13. **白天背景 A+B**（`pageBackground.tsx`）：A=顶部 `pageBackgroundTop` 微品牌蓝 → 底部 pageBackground 渐变；B=`useAlbumTintColor` 封面主色 α0.05 氛围层（仅白天、失败回退 A、同封面缓存）。**深色模式不启用**。
14. **推荐歌单**：两级结构（Tags→SheetsByTag）走插件协议；**独立歌单可用率**（键 `plugin-recommend-reliability`）排序择优，与通用可用率分开统计；每日缓存键 `Plugin.RecommendCache`/`RecommendTagCache`/`TopListCache`（每日一次防封禁，8s 超时兜底）；"设为推荐源"已删除（来源选择在三级浮窗内）。
15. **尺寸**：组件一律固定 dp（见字体/图标档位）；rpx 仅保留按屏比例元素（弹窗宽 60%/86%、网格 gap、沉浸层光带特效）；`rpx(n)=n/750×短边`，手机 360 与平板 800 漂移 2.2 倍，禁止新组件用 rpx。
16. **文件路径**：RNFS 自动剥离 `file://` 前缀；传给 mp3Util 前需自行剥离；统一以 raw 路径流转，播放时 `addFileScheme`。

> ⚠️ 修正（背景渐变方向）：来源《二次开发指南.md》第 13 条称"A=顶部 `pageBackgroundTop` 微品牌蓝 → 底部 pageBackground 渐变"。经核对 `src/components/base/pageBackground.tsx:54-59`，实际 LinearGradient `colors=[pageBackground, pageBackgroundTop]`、`start=(0.5,0)`→`end=(0.5,1)`，即**顶部=pageBackground（#F8F9FA 白）、底部=pageBackgroundTop（#EAF0FA 微蓝）**，与原文方向相反。`src/core/theme.ts:19-22` 注释亦明确"顶部 pageBackground → 底部 pageBackgroundTop，顶部白、底部浅蓝"。以代码为准。
>
> ⚠️ 修正（封面氛围层方向）：来源 PROJECT_DECISIONS 称"B：背景顶部叠加封面主色 α0.05→0"。经核对 `pageBackground.tsx:78-83`，实际 `colors=[Color(tint).alpha(0), Color(tint).alpha(0.05)]`、start 顶 end 底，即**顶部无 tint、底部带封面氛围 α0.05**（代码注释"顶部无、底部带封面氛围"）。以代码为准。

### 1.7 已踩的坑（防复发）

| 坑 | 现象 | 根因 / 解法 |
|---|---|---|
| 构建无产物 | 后台构建跑完 APK 时间戳不变 | Gradle daemon 复用失败（历史 11 个 busy daemon）；用 `run_in_background` + 日志落盘 + 轮询产物时间戳，构建日志看 `$env:TEMP\gradle_build.log` |
| gitee raw 404 | 更新检查 raw 链接偶发 404 | gitee raw 有 UA 反爬；只作兜底，主链路用 release 附件直链 |
| gitee 附件上传名错 | 附件名变成 `file=@path;filename=...` | multipart 必须显式 `-F "file=@path;filename=xxx"`，否则 curl 自动加前缀 |
| gitee release 删附件 405 | 想换新 APK 删旧附件报 405 | 不能删 release 内附件 → **删除重建整个 release**（固定 tag `latest`） |
| 白底图露白角 | 候选图标贴浅色底出现白色直角 | 生成图是纯白底；必须先按主体色包围盒裁边 + 圆角 mask 抠成透明（`make_brand_v4.py`），勿直接整图贴 |
| image_edit 延展失真 | 启动页图标显示不全/歪斜 | 品牌图延展改用**程序化合成**（Pillow 像素级直贴），不依赖文生图/图生图 |
| 浮窗错位 | 三级弹窗出现在屏幕中心而非内容区中心 | 浮窗父容器必须在内容区容器内（不含 tab），用 absoluteFill+center |
| 裸宽度判断 | 平板布局异常 | 统一 `useIsTablet`，600dp 分界，全 src 裸宽度 = 0 |
| 状态栏白图标 | 二级页弹出后状态栏变白 | `StatusBar` 默认参数改跟随主题；二级页不覆盖状态栏 |
| 版本号检测不到更新 | 升版后检查仍说最新 | version.json 的 `version` 必须 **> 当前安装版本**；多段版本号（0.6.2.1）compare-versions 支持 |
| 下载目录/权限 | 下载失败 | 路径走 FileProvider 授权目录；权限页已改三级浮窗（悬浮窗/文件读写开关） |
| 沉浸页歌词底部不对齐 | 歌词区下端比封面高/低 | 平板 `lyricWrapTablet` 已有 paddingBottom 64，**勿在 leftPane 再叠加**（双重 64 = 128 反而上移）；手机竖屏无 coverPane 不受影响 |
| 背景取色每切歌抖动 | 切歌背景色跳变 | 封面主色 α 压到 0.05 以下 + 同封面 URL 缓存（useAlbumTintColor）；取色失败回退 A 渐变 |
| 暗色模式图标不可见 | 音量等图标暗色下隐形 | svg `stroke` 硬编码深色 → 改 `currentColor` 跟随主题；新图标禁止写死颜色 |
| 历史 rpx 残留 | 手机/平板尺寸漂移 2.2 倍 | 新代码一律固定 dp；历史 rpx 按"组件固定 dp、比例特效保留"原则清理（歌词拖拽浮层 76/84/152、歌单封面 176 已修） |
| GitHub push 认证/连接失败 | Authentication failed 或连不上 443 | 国内访问 github.com 间歇不通，多试几次或稍后重试；token 被拒时换用户提供的备用 token（均需写权限） |

### 1.8 发版与更新

概要（完整流程见第2章）：

### 2.1 版本与插件兼容策略（2026-10-08）

**背景**：插件安装时，App 会校验当前版本号是否满足插件声明的 `appVersion` 范围（semver，如 `>=0.6.0 <0.7.0`，实现见 `src/core/pluginManager/plugin.ts` checkValid）。不满足 → 插件标记"与 App 版本不兼容"，无法使用。部分插件不声明 `appVersion`，永不参与校验。

**现状**：极悦界版本 0.6.2；主流音源插件生态（musicfree-plugins）范围围绕 MusicFree 0.6.x 声明，当前兼容。

**决策**：
1. **主策略**：版本号跟随 MusicFree 上游版本线（0.6.x 小版本递增），不主动跳大版本；插件生态更新范围时自然兼容。
2. **跳大版本预案**：若未来需跳到 1.x，实施"兼容线校验"——校验时用映射的兼容版本（如 0.6.2）匹配插件 `appVersion`，而非真实版本号；真实版本号照常升，插件兼容不受影响。
3. **兜底**：可把"不检查插件版本"（`basic.notCheckPluginVersion`）默认值改为开，代价是失去兼容性提示。

### 2.2 界面层级最深约束（2026-10-08）

**决策**：一般**三级页面就是最底层界面**（不再往下层）；迫不得已需要在三级页面下再弹出窗口时，**弹出的页面仍必须遵守三级页面的规范**（顶部渐变标题行、底部等高同渐变选项行、平板右内容区中心定位等）。

### 2.7 音源排序页修复与可用率排序生效（2026-10-09）

**背景**：用户反馈"排序页点按可用率/按平台，列表上方有空白"。核查（全程只读源码）定位三处问题：

1. **列表上方空白（用户点名）**：`pluginSort.tsx` 顶部 `marginTop = rpx(188) + StatusBar.currentHeight` 本为拖拽坐标换算专用（`SortableFlatList` 内部 `offsetRef = pageY - marginTop`，**不参与布局**）；但非手动模式（reliability/platform）的普通 `FlatList` 直接 `style={{ marginTop }}` → 列表被顶出 188rpx+状态栏 空白。**修复**：移除该样式。

**gitee API 踩坑（本次实测）**：
1. **创建 release 用 `curl -d '{"tag_name":...}'`（JSON）→ 400**；改用 **`-F` 表单方式**（`-F access_token=... -F tag_name=latest -F target_commitish=master`）→ 201 成功。后续创建 release 一律用 `-F` 表单。
2. **创建 release 必须带 `target_commitish`**（如 `master`），否则 400。
3. **删除 release 不删 tag**：直接 POST 重建同名 tag 仍 400（tag 残留冲突）。流程=先 DELETE release → 确认 tag 已随 release 消失（若残留则 DELETE tags/latest）→ 再 POST 重建。
4. **PATCH 更新 release 名称/正文必须带 `tag_name`**（否则 400 `tag_name is missing`）；`-F` 表单传中文 name/body 正常（JSON 中文曾 400，疑似编码）。
5. 附件上传：`POST releases/{id}/attach_files?name=xxx -F "file=@path;filename=xxx"`（201）。删除 release 内附件 405 → 必须重建 release。
6. 本地 `git commit` 会被上游 **lint-staged 钩子**拦截（npm run lint 失败 → 自动回滚暂存，工作区改动保留）。**不要用 --no-verify**；如需提交快照，先修 lint 或改走其他方式（历史一直以工作区未提交状态开发，commit 非必需）。

**GitHub 上传**：既定意图=源码+包上传 GitHub（`xunwulove`），但现有 token 实测只读（push/建仓 403）；需用户提供**有写权限的 token** 才能自动推送，或手动上传。gitee 更新链路不受影响。

## 第4章 Onboarding 设计方案

> 来源：《docs/onboarding-设计方案.md》。状态：**已实施**（2026-10-12，代码完成 + tsc 通过，待打包装机验证）。依据：Android 场景化权限申请惯例 + 同类软件（MusicFree/洛雪/网易云/QQ 音乐）引导做法核查结论。

### 4.1 目标

全新安装后首次启动，主界面出现前展示全屏引导页；完成后持久化标记 `app.onboardingDone`，之后不再出现。跳过则不写完成标记，下次启动仍会提示（引导页全程可跳过）。

### 4.2 触发与衔接

- 触发：首次启动，主界面渲染前检查 `app.onboardingDone` 未设置 → 展示引导页。
- 完成：写 `app.onboardingDone = true`，同时兼容处理旧的 `app.skipBootstrapStorageDialog`（引导完成后不再弹现有"存储权限"对话框）。
- 设置页"权限管理"入口保留，可随时补开权限。

### 4.3 结构：3 屏，左右滑动

底部进度点 + 主按钮，左上角常驻"跳过"。

**第 1 屏 · 欢迎（品牌页）**
- 品牌图 + "极悦界" 大字
- 标语：本地优先 · 多音源聚合 · 数据都在本机
- 一句话价值说明：导入音乐源、搜索全网歌曲、下载到本地
- 按钮：下一步

**第 2 屏 · 权限（精简为 2 项，符合 Android 场景化申请惯例）**

| 权限 | 用途说明 | 交互 |
|---|---|---|
| 文件访问 | 扫描设备上的本地音乐，并把下载的歌曲保存到本地 | 点击 → 跳系统设置开启 → 返回自动检测，状态实时刷新为绿色对勾 |
| 通知（Android 13+） | 下载完成、后台播放时提醒 | 点击 → 系统弹窗授权 |

- **不列入引导页**：安装应用（到"软件内更新"时再引导）、悬浮窗（设置页权限管理里保留，悬浮歌词功能可选用）
- 理由：引导页权限列得越多，用户越可能全拒或整体跳过（同类 App 均为"用到时再申请"）

**第 3 屏 · 音源就绪 + 快速上手**（替代"偏好设置"——新用户无偏好基础，选音质/下载位置无感知价值）
- 说明卡片："已内置常用音源，搜索/听歌/下载即刻可用"，展示当前已启用音源数量
- 开关 1：**"自动更新音源"**（默认开，对应设置页 `basic.autoUpdatePlugin`；引导结束后立即拉取一次内置订阅源）
- 开关 2：**"扫描本地音乐"**（默认开，引导结束自动扫描，避免音乐库空态）
- 开关 3：**"进入软件自动播放"**（默认跟随设置页 `basic.autoPlayWhenAppStart`；启动后自动续播上次的歌曲）
- 不引导用户选择默认音质/下载位置（保留默认，可在设置页修改）

**结束**："开始使用" → 进入主界面。若用户跳过扫描且本地音乐库为空：音乐库空态显示"去扫描"引导按钮。

### 4.4 复用现有能力

- 权限状态检测/返回自动刷新逻辑：复用 `PermissionSettingDialog`（permissionSettingDialog.tsx）的 `NativeUtils.checkStoragePermission` / `LyricUtil.checkSystemAlertPermission` + AppState 监听机制
- 音源启用数量：`usePlugins()` + `pluginManager.isPluginEnabled`

- **usePanel 单槽位**（`usePanel.ts`）：GlobalState 单槽；showPanel 时若已有面板先 emit("hidePanel") 排队 callback；hidePanel 支持 immediate（跳过动画）+ callback；`index.tsx` 用 React.memo(() => true) 包裹。
- **PanelBase 浮出层基座**（`base/panelBase.tsx`）：浮出层（非居中对话框）体系的统一基座，弹出位置与滑入方向随设备/方向分三种（代码注释明确"平板：遮罩与面板限制在右内容区——左 30% 播放区 + 顶部 tab 栏不被遮挡"）：
  - **手机竖屏**：底部上滑（translateY、默认高 vh(60)、bottom:0、顶部圆角 14）。
  - **平板横屏（项目主场景，且非全屏播放）**：**右侧浮出层**——left 30%/width 70%/top 56(TAB_BAR_HEIGHT)/bottom 0，translateX 从右滑入；不遮左 30% 播放区、不遮顶 tab 行。
  - **positionMethod='top'**：自顶部下滑（如 SetUserVariables、SearchLrc）。
  - 全屏播放层激活时为例外（全屏覆盖、点面板外任意处关闭）。遮罩 #000 opacity 0.5；zIndex mask 15000 / panel 15010；动画 250ms Easing.out(exp)。
- **PanelFullscreen 全屏基座**（`base/panelFullscreen.tsx`）：width/height 100%；动画 SlideToTop（默认）或 Scale（0.3→1.0）；有遮罩 #000 opacity 0.5，无遮罩时面板底 colors.background。
- **PanelHeader 面板标题栏**（`base/panelHeader.tsx`）：标题 title(18)+bold(700)；取消/确定 subTitle(14)+medium(500)；渐变底 primary α0.14→α0.04 对角 start(0,0)→end(1,1)；取消按钮默认 text 色、确定按钮 primary；行高 56、paddingHorizontal 16、左右按钮宽 72、标题 flex:1 居中、下方 Divider（可关）。
