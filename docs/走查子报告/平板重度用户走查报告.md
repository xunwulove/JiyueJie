# 极悦界（Jiyuejie）平板重度用户走查报告

- 走查版本：0.6.2.15（源码静态走查，未真机运行）
- 走查视角：平板横屏重度用户——听歌看封面、边看歌词边逛歌单
- 走查方式：通读指定范围源码；本环境无 adb/模拟器/真机，**所有界面级现象均为代码推断，已在"未验证项"集中声明**
- 只读走查，未修改任何代码

## 1. 画像与使用场景

- 设备：10 寸级平板，横屏为主（短边 ≥600dp），偶尔竖持；可能涉及折叠屏展开/Android 分屏。
- 典型动线：
  1. 横屏首页看左侧常驻播放面板（封面+当前歌词+进度条），右侧逛"音乐库/我的/搜索"。
  2. 点左面板 → 全屏播放页（6:4 分栏，左歌词控制右大封面）；静置 15s 进沉浸歌词层。
  3. 从右侧歌单/专辑/歌手页一层层点进去（覆盖层从右滑入），硬件返回逐级回退。
  4. 横屏拿在 40cm 外听歌，最怕：字小、按钮小、宽屏被浪费、转个向布局乱掉、切后台回来状态丢了。

## 3. 确定 bug 清单

| 严重度 | 文件:行号 | 触发条件 | 后果 |
|---|---|---|---|
| **P1** | `src/components/panels/base/panelBase.tsx:135-143, 193-201` | 平板横屏（orientation=horizontal）下从左面板点"队列"或从歌曲菜单弹出任意 Panel（如 PlayList） | 遮罩 mask 按 `top:56` 限在 tab 栏之下，但面板本体只取了 `left/width`，竖向为 `height=vh(100)-insets.top; bottom:0` → 面板顶边 = `insets.top`（≈24dp），**整块面板从状态栏高度起画，正好盖住高 56dp 的顶部 4-tab 栏**，违背该文件 131 行注释"顶部 tab 栏不被遮挡"的硬约束；遮罩与面板上下不对齐（y≈24~56 区间有面板无遮罩）。需真机复核视觉，但几何推导成立。 |
| **P2** | `src/pages/home/components/tabletPanel.tsx:305-320` | 在左侧常驻面板拖进度条 | Slider 直接受控于 `value={progress.position}`（默认 500ms 刷新），**无 onValueChange、无 slidingRef 锁值**；对比同项目全屏页 `bottom/seekBar.tsx:40-56` 的标准写法（onSlidingStart 锁值 + onValueChange 预览 + onSlidingComplete 才 seek）。拖拽中拇指每 500ms 被真实位置拉回，手感跳跃、无时间预览。 |
| **P2** | `src/utils/rpx.ts:3-9` | 折叠屏展开/Android 分屏/旋转后窗口尺寸变化 | `windowWidth/minWindowEdge` 在模块首次加载时取一次快照，不订阅 Dimensions change；而 `vw()/vh()` 是实时计算。两者混用后，所有 rpx(XX) 的 padding/字号/卡片宽度停留在启动尺寸，与实时布局错位。（同一台设备单纯横竖屏切换短边不变，影响小；折叠/分屏影响大。） |
| **P2** | `src/pages/musicDetail/components/immersiveLayer.tsx:48` | 进入沉浸层后发生横竖屏旋转 | `const { width: SCREEN_W } = Dimensions.get("window")` 模块级快照；流光带位移 `[SCREEN_W, -SCREEN_W]`、光斑尺寸 `SCREEN_W*0.62` 均用旧宽度，旋转后光带扫入/扫出范围与屏幕不匹配。 |
| **P2** | `src/pages/home/components/subPageOverlay.tsx:49-73` + `src/core/tabletNav.ts:27-31` | 在二级页栈上按硬件返回/返回按钮 | `popTabletSubPage` 直接从 atom 栈移除顶层帧，顶层覆盖层**瞬间卸载、无右滑出退场动画**（入场有 240ms 滑入，退场没有），只有一级内容回弹。 |

> 说明：未发现 P0（崩溃/数据丢失/核心功能不可用）级问题。`tabletPanel` 封面高度预算（tabletPanelBudget.ts）在最短 600dp 矮屏上 coverBudget≈106dp，不会出现负预算重叠；`useIsTablet`/`useOrientation` 均已正确订阅尺寸变化。

## 4. 可优化建议

### P1 功能性
- **面板本体 top 对齐遮罩**：`panelBase.tsx` 横屏平板分支给 panelBody 也加 `top: TAB_BAR_HEIGHT`（或 `insets.top + 56`，与 mask 的 `tabletBound.top` 对齐），让队列/歌曲选项面板不再压住顶部 tab 栏。（`panelBase.tsx:193-201`）
- **左面板进度条对齐 seekBar 标准写法**：加 `slidingRef` + `onValueChange` 预览态 + 滑完才 `seekTo`，与全屏页手感一致。（`tabletPanel.tsx:305-320`）

### P2 体验
- **二级列表宽屏利用率**：`searchMusicList/index.tsx`（isTablet 仅用于关 autoFocus，34/51 行）、`sheetDetail/index.tsx`、`apiSheetDetail`、`albumDetail`、`artistDetail`、`topListDetail` 等全部是手机单列整宽列表，在 ~896dp 宽覆盖层里每行拉得过长、单行信息稀稀拉拉。建议：列表内容居中限宽（如 maxWidth 720~860dp）或双列卡片化。
- **rpx 响应化**：`rpx.ts` 改为订阅 Dimensions change 的 hook 或导出 `useRpx()`，折叠/分屏后间距字号跟着变。
- **左面板小按钮触摸目标**：循环模式图标 `size=20`（`tabletPanel.tsx:340`）、队列图标 `size=20`（`tabletPanel.tsx:383`），Icon 组件本身就是按 size 尺寸的可点区域、且这两个按钮**没有像 playControl 那样加 hitSlop**；平板上属于偏小热区，建议图标或热区加到 ≥40dp。
- **pop 覆盖层退场动画**：pop 时给顶层帧加一段右滑出再卸载（或维护 `closingKey` 态），对称入场动画。
- **沉浸层 SCREEN_W 改 `useWindowDimensions()`** 实时取值，旋转后光效几何正确。
- **竖屏平板体验**：竖持平板（短边≥600）首页是 30/70 分栏，但全屏播放页用 `orientation==="horizontal"` 判定（`musicDetail/index.tsx:37`、`immersiveLayer.tsx:105`、`playControl.tsx:31`）→ 竖持时退回手机单列。建议统一判定口径（短边法），或在竖屏全屏页也做单列紧凑优化。
- **玩家会想要的**（当前缺失）：歌单长按批量管理在宽屏双栏对比、播放队列面板在右内容区做成常驻侧栏而非弹层、外接键鼠时的空格/方向键快捷键、分屏多任务时右侧副屏联动。

## 5. 未验证项（诚实声明）

1. **bug#1 的实际视觉效果**——面板是否真的压住 tab 栏，几何推导成立但无真机确认；建议优先在平板上点一次"播放队列"目视确认。
2. 旋转时左侧面板封面重算（onLayout→coverSize）是否有一帧闪烁/歌词 FlatList 滚动位置是否保持。
3. 折叠屏展开瞬间 `useIsTablet` false→true 切换时，home 手机分支→平板分支的首帧布局。
4. App 切后台再回前台后，subPages 栈、全屏层、歌词滚动位置是否原样恢复（jotai atom 内存态，冷启动后是否恢复未深查）。
5. 720p 兜底判定（`tablet.ts:13-16`，density≤1.75 且短边 px≥720）在车机/低端大屏上的实际触发与面板预算表现。
6. `dialogs/base` 与 `panelBase` 在 fullPlaying=true 时全屏弹出后的遮罩/对齐（代码已按 fullPlaying 解除 bound，未实测）。
7. 触摸热区实测尺寸（Icon 根节点是否整 size 区域可点未单独验证组件行为）。
