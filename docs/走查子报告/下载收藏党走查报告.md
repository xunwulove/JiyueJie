## 1. 画像与使用场景

- 身份：批量下载党，习惯整页/整歌单选若干首 → 下载 → 丢进自建歌单整理。
- 最在意：下载失败能重试、断网/被杀进程后任务不丢、文件好找、歌单/历史/统计重启后还在。
- 典型操作链路：
  1. 在歌单编辑器勾选 N 首 → 底部「下载」批量发起（`musicListEditor/components/bottom.tsx:70-79` 已支持）。
  2. 进「下载管理」看进度、删失败项。
  3. 下载完的歌自动入「本地音乐库」（`downloader.ts:384`），再整理进自建歌单。
  4. 偶尔看「听歌统计」和「最近播放」。
  5. 换机/重装前走「歌单备份/恢复」。

## 4. 可优化建议

### P1（功能性）
1. **下载队列卡死自愈**：`downloader.ts:286-305` 的 prepare catch 块末尾补一句 `this.downloadNextPendingTask()`，并在 UI 上给失败任务加「重试」（重新走 `download(musicItem)` 即可）。
2. **歌单删除歌曲后 worksNum 不刷新**：`musicSheet/index.ts:425` 改为 `await this.updateMusicSheetBase(sheetId, patchData)`，或像 `removeMusicByIndex` 那样单独再 `produce` 一次 worksNum。
3. **统计算法**：`statistics/index.ts` 要么改用历史里的 `playCount` 字段做累计、`playedAt` 只做「最近一次」展示；要么在 `musicHistory` 里单独维护一份「按天聚合的播放次数/时长」表，否则统计数字对用户是误导。
4. **60s 过滤把 duration=0 也排掉**：`localMusicSheet.ts:327-329` 改为 `_.duration > 0 && _.duration < minDuration` 才过滤，损坏文件单独提示或进「无法识别」分组。
5. **断点续传 + 队列持久化**：`downloadTasks` / `downloadQueueAtom` 落 MMKV；`downloadFile` 检查 cache 文件大小并加 `resume`；启动时清理 `downloadCachePath` 下残留的半截文件。

### P2（体验/下载党想要的）
1. **批量下载一首歌单/专辑**：`musicListEditor` 已有勾选下载，但歌单详情页、专辑详情页缺「整页下载」入口（未验证是否已存在，标未验证）。
2. **下载音质选择**：当前下载用 `basic.defaultDownloadQuality` 全局默认（`downloader.ts:261`），发起下载时不弹窗让用户选。
3. **下载完成系统通知**：`downloadFile({background:true})` 开启了后台，但代码里未见完成通知；下载党批量下完切回 App 才知道。
4. **WiFi 下自动下载/仅充电时下载**：未见相关逻辑。
5. **自定义存储位置**：配置项 `basic.downloadPath` 存在，但「下载设置」Dialog（`showDialog("DownloadSettingsDialog")`，`downloading/index.tsx:21`）的具体 UI 未在本次走查范围内细读，**未验证**是否暴露路径选择。
6. **已下载列表与本地音乐库联动删除**：`removeDownloaded` 应同时 `LocalMusicSheet.removeMusic(musicItem, false)`。
7. **备份范围扩展**：`backup.ts` 应把 history / downloadedList / scanSettings / appConfig（下载相关 key）一并打包。
8. **下载完成后自动嵌入封面失败无日志**：`downloader.ts:378-383` `.catch(()=>{})` 建议至少 `errorLog` 一下。
9. **历史页单曲删除**：复用 `musicHistory.removeMusic` 即可，UI 加个左滑操作。
10. **重名歌单提示**：`addSheet` 前检查 `musicSheetsBaseAtom` 是否已有同 title，弹确认。
