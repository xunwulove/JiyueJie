## 四、验证链路

### 1. 电脑验证（Node vm 模拟宿主，无需装机）

```bash
cd E:\xunwu\deepseek\jiyuejie\tools\verify_sources
node verify_downloads.cjs   # ① 全量拉清单（gitee plugins.json 21 源）→ 下载 + node --check 语法检查 → 存 dl2/<name>.js
node verify_mf.cjs          # ② 五维执行验证（输出五档报告 + probe-report.json）
```

- **verify_downloads**：逐个下载音源脚本（github 优先国内镜像 ghproxy.net / gh-proxy.com，gitee / jsdelivr / fastly / moro 直连，与 App 逻辑一致）。
- **verify_mf（五维）**：沙箱加载插件（兼容 `exports.default` / `__musicFreeCore__`）→ **搜索**（music→song 兜底，样本"海阔天空"）→ **解析**（getMediaSource 按 standard→high→lossless 取链）→ **播放**（Range 前 64KB，Content-Type 非 text/html|text/plain|application/json 才算可播）→ **歌词**（getLyric，rawLrc/translation 非空）→ **歌单**（getRecommendSheetTags → getMusicSheetInfo → 第一首可解析且可播，记录 sheetMs）。工程参数：**并发 5、总预算 120s、单步超时保护**；插件自身 console 已静音（防刷屏）。
- 音源脚本存 `dl2/`（21 个 MF 源副本）；`node_modules/` 为 vm 运行依赖。

### 2. 真机验证（最终口径）

| 手段 | 说明 |
|---|---|
| 独立探测 App（`tools/source-probe/`） | 装机实测：真实 QuickJS 引擎跑插件判"可播"；清单来自**订阅拉取**（默认 gitee `sources/plugins.json`，可在"订阅设置"添加自定义订阅链接，增量更新，无需重打包） |
| App 内探测（`probeService.ts`） | 软件内"检测音源"：**2026-10-24 起探测运行互斥**（整轮锁，防并发）；串行 + 源间 1.5s，**总预算 120s**（由 60s 放宽），单步超时保护（歌词 5s / 歌单各段 8s），失败不重试 |

> 真机判定是最终口径：电脑脚本能快速判"可搜+可取链+可下载"，但**能否真正播放以 App 内听感为准**（防盗链/临时签名/地区限制脚本无法完全模拟）。

## 五、探测维度与结果处理

### 维度总表（7 维能力面）

| # | 维度 | 探测内容 | 判据 |
|---|---|---|---|
| ① | 可下载/可加载 | URL 可达、脚本可下载、JS 语法有效、沙箱能加载执行 | 失败 → X |
| ② | 搜索能力 | 能否搜到歌（多关键词任一命中，规避单词盲区） | 空 → C |
| ③ | 播放取链 | 能否解析真实播放地址（歌自带 url → `getMusicUrl` → `getMediaSource`） | 取不到 → B1 |
| ④ | 地址可访问性 | HTTP 200/206 且 Content-Type 为音频类（防假阳性：403=防盗链、HTML/JSON 错误页=不可播） | 403→A1 / 失败→B2 |
| ⑤ | 歌单能力 | 推荐歌单/用户歌单/榜单能否拉到非空列表（对应 App 推荐歌单功能） | 达标/否 |
| ⑥ | 登录类标记 | 插件含 login/verifyToken → 标注"需登录" | 标记 |
| ⑦ | 可用率（App 内） | probeService 逐源探测统计，音源管理按可用率降序 | 0~1 |

### App 内探测口径（probeService 5 维，2026-10-25 补全）

软件内"检测音源"逐源探测 **5 维**（仅对具备对应能力的源探测；不具备则该维度不记录、不误伤）：

| 维度 | 探测内容 | 记录位置 | 判据 |
|---|---|---|---|
| 搜索 | `search("海阔天空",1,"music")` | 合成可用率（权重 10%） | 有结果 |
| 解析 | `getMediaSource` 按音质序取链 | 合成可用率（权重 30%） | 有播放地址 |
| 播放 | 深度模式静音 ExoPlayer ≥2s（音量 0、不抢焦点、不打断当前播放） | 合成可用率（权重 60%） | 播放位置推进无错 |
| 歌词 | `getLyric`（搜索结果第 1 首，5s 超时） | 歌词可用率（独立） | 返回 rawLrc/trans 非空 |
| 歌单 | `getRecommendSheetTags`（8s）→ 真实歌单/标签 → `getMusicSheetInfo`（8s）拉歌曲 → 歌单第 1 首解析（深度再静音可播） | **推荐歌单可用率（独立 recommend 统计）** | **歌单能显示（列表非空）+ 内容可播（第一首有地址/可播）** |

> 歌单维度**独立于合成可用率**：歌单显示有问题但播放路径正常的源，不会被歌单维度拖累合成可用率。自动探测（轻量，每日一轮）做搜索/解析/歌词/歌单显示，不做播放；手动"检测音源"全量深度（含播放）。**自动探测按维度过滤 + 维度级执行**：只探测 search/parse/lyric/sheet 中**缺失或 >24h 未探测的维度**，已验维度不重跑；play 维度只由手动深度维护。**真实播放成功会刷新 play 维度探测时间戳**（播放过即证明可播，24h 内不再重复探测播放功能；播放失败不刷新）——其余维度（搜索/歌词/歌单）只由探测本身刷新，用户使用行为不豁免。
>
> **播放退化（可播→仅可搜）的发现机制**：自动探测不做播放，退化不靠自动轮发现——兜底是①**用户实际播放失败会记 `recordPlayResult(false)` 进 play 维度**（可用率下降 → 排序下沉 → 音源管理可见）；②手动"检测音源"深度探测刷新 play 维度。

### 档位 → 动作

| 档位 | 含义 | 处理 |
|---|---|---|
| **A** | 可搜 + 可播 | **入正式清单**（`--publish` 只收 A 档） |
| **A1** | 可搜 + 防盗链 403 | **人工复核**：App 内点播确认，通过可手动补入 |
| **B1** | 可搜但取不到地址 | **人工复核**（可能需登录/参数/特定音质） |
| **B2** | 取到地址但探测失败 | **人工复核**（4xx/5xx/超时/非音频 200） |
| **B** | 可搜未验播（`--play=0`） | 视需要重跑播放验证 |
| **C** | 仅可达未搜到（限流重试后仍空） | 不入选，观察/换源 |
| **X** | 失效（下载/加载失败/无搜索接口） | **下架/排除** |
| 需登录 | 含 login/verifyToken | 标注，App 内复核能否免登录使用 |

> 定时监控（probe_plugin.js `--interval`）对比每轮，输出：新增失效 / 恢复可用 / 升级可播 / 可播→仅可搜 / 新增 / 移除。

### 探测报告（report.ts v2，2026-10-25 改进）

- **五档分类**（按用户价值）：🟢 **全通**（真能播放）/ 🟠 **可解析不可播**（半死源，可修复）/ 🟡 **半可用**（部分能力可用）/ 🟣 **歌单型源**（搜索无结果属正常，非失效）/ 🔴 **死源**（全能力失败）
- **"可解析不可播"单独成节**：能搜索、能取链但真实播放失败——**不是死源**，按失败原因处置并附**建议动作**列：403/鉴权→补 headers/Referer；404→直链失效；网络/超时/缓冲→接口不稳定或直链时效短（播放时动态取链）；格式不支持→URL 实际格式与插件声明不符
- **全部明细全字段**：每个音源一行展示——5 类搜索逐个 ✓/✗（单曲/专辑/歌手/歌单/歌词）+ 解析/播放/歌单/歌词/翻译/歌手作品/专辑/评论 + 样本歌曲 + 失败原因 + 耗时
- **失败原因标准化**：`classifyPlayError` 归一（403/404/网络/格式/鉴权等）后聚合统计，替代原始报错字符串
- **播放验证静音**（playback.ts）：深度播放验证 `setVolume(0)`——验证只依赖缓冲/解码/状态机（进入 Playing + 持续 ≥2s 无错），与音量无关，探测过程**不出声**

### 发布流程（gitee contents PUT）

音源随软件同仓托管于 **gitee `xunwulove/jiyuejie`**，路径 `sources/plugins.json`：

1. **GET** `https://gitee.com/api/v5/repos/xunwulove/jiyuejie/contents/sources/plugins.json` 拿当前 `sha`；
2. **PUT** 同接口，`content` 为 **base64** 编码的新 plugins.json，带 `sha`（Gitee contents 接口必带 base64，传明文会被静默存成乱码）；

## 七、App 内生效

- 软件默认订阅地址 `DEFAULT_PLUGIN_SUBSCRIPTION_URL` = gitee `sources/plugins.json`（`src/constants/`）。
- 用户在 **音源管理 → 更新订阅**（或自动更新音源开启）→ 拉取 plugins.json → 增量更新插件 → 生效。
- App 内仓库信息（关于页"更新与音源"卡片）指向 gitee 仓库。

### 7.1 订阅同步清理机制（2026-10-26）

增量更新只增不删会造成「清单移除的旧源长期滞留、无用源越积越多」。极悦界已实现**来源标记 + 连续 2 轮自动卸载**：

**来源标记（sourceTag）**——每个已装插件记录来源：

| 来源 | 标记 | 安装入口 |
|---|---|---|
| 订阅清单安装（自动更新 / 手动「更新订阅」） | `{ type: "subscription", url: <订阅地址> }` | `updatePluginsFromSubscription`、`onSubscribeClick` |
| 手动导入（本地文件 / URL 直装 / 深链 `musicfree://` / 备份恢复） | `{ type: "manual" }` | `installPluginFromLocalFile`、`installPluginFromUrl(config)`、`bootstrap` 深链、`backup.ts` |
| 软件内「更新插件」（维护者更新，走 `instance.srcUrl`） | **继承旧标记** | `installFromCode`：`config.sourceTag ?? oldVersionPlugin.sourceTag` |

**清理规则（仅影响订阅来源）**：

1. 每次订阅更新（**自动更新 / 首启引导 `updatePluginsFromSubscription` / 手动「更新订阅」`onSubscribeClick`** 共用 `cleanupSubscriptionPlugins`）解析清单后，对**来源=当前订阅地址**的已装插件：
   - 本轮在清单 → `missingRounds` 清零；
   - 本轮不在清单 → `missingRounds += 1`（持久化到 `plugin.cache` MMKV）；
   - `missingRounds >= 2`（**连续 2 轮**不在清单）→ 自动卸载（复用 `uninstallPlugin`：删文件 + 移除 + `removeAllMediaExtra`）。
2. **误删防护（跨订阅共用源）**：同名插件仍在本轮**其他订阅地址**清单中 → 只累计不卸载，避免"源在别的订阅还在用，却被本订阅移除误删"。
3. **手动导入（manual）的源永不自动清理**；其他订阅地址装的源只受其自身订阅的清单变动影响。
4. **手动源的标记优先级最高**：即使订阅清单后来包含同名源且版本更高，`installFromCode` 也不会把 manual 覆盖成 subscription（防止手动导入源被误清）。
5. 同一源被手动导入后再被订阅清单收录 → 保持 manual，不受清理影响。

> 理由（2026-10-26 用户拍板）：不用「可用率=0」判定（可用率判定在维护清单时已做、单轮可用率受抖动不可靠、与移出清单自相矛盾）；用「来源归属 + 连续 2 轮不在清单」（2 轮缓冲防「移出又加回」反复装卸）。
>
> **新增/更换音源时注意**：正式清单 `sources/plugins.json` 每更新一次，已装用户按「更新订阅」后，旧清单移除的源会在**连续 2 轮**后自动消失，无需手动卸载。

## 八、测试执行 SOP（探测闭环执行手册）

> 执行一轮"探测测试"时的责任分工与顺序；工具细节见上文各章节，此处只写**谁做什么、交接什么、何时能进下一步**。**测试结果不落档**：音源时效性短，今日可播明日可能失效，历史测试结果无保留价值，每轮按当轮实际结果走，不写执行记录。

## 九、日常维护建议

1. 新增/更换音源：`verify_downloads.cjs` 确认可下载可加载 → `verify_mf.cjs` 五维报告确认可搜可取链可播 → 装机（探测 App 或 App 内检测）确认真实可播 → 只有 A 档入 `sources/plugins.json`。
2. 发布走 gitee contents PUT（base64 + sha），发完验证直链。
3. 定期用 probe_plugin.js 定时监控（`--interval`）发现失效源，及时下架/换源。
4. 音源脚本若大量更新，同步刷新 `tools/verify_sources/dl2/` 副本。
5. **从正式清单移除失效源后**：已装用户的源带 subscription 标记，连续 2 轮「更新订阅」自动卸载（见 §7.1），无需用户手动处理；但要**保证订阅地址不变**（换了订阅地址 = 旧源不再属于任何当前订阅，将永远不会被自动清理）。
