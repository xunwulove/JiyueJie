## 一、背景

按调研结论（MexMp3 开源播放器方案最贴近本项目）：**ExoPlayer + android.media.audiofx.Equalizer 绑定 audioSessionId**。
本项目播放器是 RNTP（react-native-track-player 4.1.1，ExoPlayer），RNTP 未开放 audioSessionId 与 audiofx 绑定，因此做了原生模块 `SoundEffectModule`，**用反射**从 RNTP 内部取 ExoPlayer 的 audioSessionId，再 `Equalizer(0, sessionId)` 绑定。

## 二、用户遇到的现象链条（按时间）

1. 均衡器入口找不到（0.6.2.11 装上后无入口）→ 已加设置二级页（音效设置）
2. 均衡器只有按钮、不显示频段/预设 → "点击播放音乐后"才出现频段调节
3. 预设音效不生效（只有"自设"一种）
4. 页面提示 `call attach first`
5. 播放后报 `诊断: Could not find @ReactModule annotation in com.doublesymmetry.trackplayer.module.MusicModule`
6. 播放后报 `诊断：InvocationTargetException → Player is accessed on the wrong thread. Current thread: 'mqt_native_modules', Expected thread: 'main'`

## 三、根因（4 个独立问题叠加）

### 根因 1：ExoPlayer 主线程访问（最核心）
- ExoPlayer **非线程安全**，必须在创建它的**主线程**访问。
- RN 原生模块方法跑在 `mqt_native_modules` 线程，直接反射调 `getAudioSessionId()` 抛
  `Player is accessed on the wrong thread`，且被反射包成 `InvocationTargetException`（message 为 null → RN 侧只看到 "unknown."）。
- **修复**：`post` 到主线程执行 + `CountDownLatch` 同步等待（方法仍同步返回）；若已在主线程则直接执行（防自锁）。

### 根因 2：RN 新版取 NativeModule 的方式
- `reactContext.getNativeModule(MusicModule::class.java)` 在 RN 新版要求模块类带 `@ReactModule` 注解；
  RNTP 老库没有 → 抛 `Could not find @ReactModule annotation`。
- **修复**：改按注册名取：`reactContext.getNativeModule("TrackPlayerModule") as? MusicModule`。

### 根因 3：Android Equalizer 系统预设不可靠
- `SoundEffect.setPreset(index)` 依赖设备系统预设，**随 ROM 差异大、部分设备（车机/定制 ROM）为 0** → 预设音效"不生效"。
- **修复**：改为**内置 EQ 预设曲线**（`src/core/soundEffect.ts` 的 `EQ_PRESETS`，10 段、单位 millibel 约 ±12dB：摇滚/流行/爵士/古典/舞曲/重低音/电子/人声/高音增强 9 个 + 手动）。
  - UI 预设列表固定 = 手动 + 9 个内置，**跨设备统一**；
  - 应用预设 = 逐段 `setBandLevel(i, level)`（不再调 `setPreset`）；
  - 设备频段数少于 10 时取前 N 段近似（频段自低频到高频，截取方向一致）；
  - 切回手动按已存 `eqBands` 重放。

### 根因 4：反射硬编码与设备兼容
- `queuedPlayer.javaClass.superclass.getDeclaredMethod("getExoPlayer")` —— kotlinaudio 是 JitPack aar 依赖，类层级随版本可能变化，superclass 硬编码会崩。
  **修复**：`findMethod()` 沿继承链向上查 `getExoPlayer` / `getAudioSessionId`（含私有方法）。
- Equalizer/BassBoost/Virtualizer 三个效果器**逐个独立 try**：个别 ROM（车机/华为）Equalizer 构造可能失败，不能一个失败连坐其余；失败原因记入 `lastError` 供诊断。

## 五、避坑要点（以后接类似功能/改均衡器必读）

1. **RN 原生模块方法 ≠ 主线程**。任何访问 ExoPlayer/MediaPlayer/RNTP 内部对象的调用，先判 `Looper.myLooper() == Looper.getMainLooper()`，非主线程一律 post 回主线程 + 同步等待（CountDownLatch），否则必踩 "Player is accessed on the wrong thread"。
2. **RN 新版本取 NativeModule 用注册名**（`getNativeModule("TrackPlayerModule")`），不要用 `getNativeModule(Xxx::class.java)` —— 老库无 `@ReactModule` 注解会直接抛错。
3. **反射依赖第三方 aar 的类层级**：一律写"沿继承链查找方法"的通用函数，禁止 `superclass` 硬编码，依赖升级才不炸。
4. **反射异常必须透传 cause 链**：`InvocationTargetException` 的 message 常为 null，组装 `message/类名 → 最内层 cause` 再 reject，否则 RN 侧诊断全是 "unknown."。
5. **Android audiofx 预设不可依赖**：系统 Equalizer 预设（setPreset）随 ROM 差异大、部分设备为 0。要"预设"效果就自带曲线逐段 setBandLevel。
6. **audiofx 构造兼容**：Equalizer/BassBoost/Virtualizer 各自独立 try/catch，一个失败不能连坐；记录 lastError 供页面诊断，别只给 "call attach first" 这种误导文案。
7. **绑定时机**：audioSessionId 在播放器**首次播放后**才分配（RNTP 未播放过 → session 未创建）。`ensureSoundEffectAttached` 需在播放就绪后调用，页面加载时失败属正常，播放一次后自动绑定。
8. **设备频段数**：getBandLevelRange/getNumberOfBands 按设备返回，写 UI 频段条时以设备能力为准，内置预设按"截取前 N 段"近似。
