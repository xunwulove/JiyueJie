# 极悦界（Jiyuejie）音质发烧友走查报告

- 走查版本：0.6.2.15（React Native 0.76.5 + Expo 业务层；Kotlin/NDK 原生 JamesDSP 移植，库名 `libjiyuejie_dsp`）
- 走查方式：本机无 adb / 真机 / 模拟器，以下结论全部来自对源码的静态通读，未实际安装运行 APK。凡未在源码中直接验证到的现象均标注"未验证"，不臆造界面观察。
- 走查范围：`src/pages/setting/settingTypes/soundEffectSetting.tsx`、`src/core/soundEffect.ts`、`src/core/jamesdsp.ts`、`android/app/src/main/java/fun/upup/musicfree/jamesdsp/JamesDSPModule.kt`、`android/kotlinaudio/.../jamesdsp/JamesDSPBridge.kt`、`JamesDSPProcessor.kt`、`JamesDSPRenderersFactory.kt`、`android/app/src/main/cpp/jdsp_jni.c`、`jdsp/jdspController.c`、`assets/ir/` 资源。

## 1. 画像与使用场景

- 我是对失真、爆音、相位敏感的用户：会逐格推拉 15 段 EQ，开输出增益 / 电子管 / 动态低音后担心削波；切换预设、开关音效的瞬间有没有"啪"的一声；换歌后设置还在不在；插耳机 / 连蓝牙后补偿曲线还是不是对的。
- 典型场景：(a) 边听边调 EQ，要求实时出声、滑块不卡顿；(b) 用 ViPER-DDC 补偿自己的耳机；(c) 拿一首 44.1kHz 古典和一首 48kHz 电子切换听；(d) 开了一堆效果后一键"重置"。

## 4. 可优化建议

### P1（功能性 / 发烧友刚需）

1. **切歌换采样率后自动重放配置**：在 `JamesDSPProcessor.configure()` 检测到 `inputSampleRate` 与上次不同时，向 JS 发一个事件（仿 `SoundEffectReattached`），JS 收到后调用 `applyAllConfig()`。这是当前最影响"设置不丢"的问题。
   - 位置：`JamesDSPProcessor.kt:37` 附近；事件发射可仿照 `SoundEffectModule` 的 `DeviceEventEmitter` 通道。
2. **卷积器/DDC 的 IR 重采样到当前 `fs`**：在 `nativeLoadIR` 前按 `g_jdsp->fs` 对 IR 做一次重采样（核心库里已有 `JamesDSPOfflineResampling`，见 `jdspController.c:919` 与 `:1008` 的用法），或在 JS 导入时强制要求 48k 并在 44.1k 曲目中明确提示"本曲采样率与 IR 不匹配"。
3. **把"非 16bit / offload 时 DSP 被旁路"变成可见状态**：在页面底部诊断行（`soundEffectSetting.tsx:742-770`）增加一行"当前输出格式：16bit/48k，DSP 已激活 / 因高位深输出被旁路"。
4. **限幅器 / 压缩器加 UI**：`setLimiter`、`setCompressor` 已封装（`jamesdsp.ts:25,90`）但页面无入口。发烧友至少需要一个"限幅阈值"滑块（默认 0dB，可调 -6..0），避免大增益组合时限幅器一直被触发、听到明显的泵感。
5. **一键重置时同步复位 `sound.eqEnabled / sound.eqPreset / jdsp.postGain 值显示`**，并在复位后立即 `applyAllConfig()` 保证 UI 与原生一致。

### P2（体验 / 细节）

1. **开关 / 切预设加 20–50ms 线性淡入**：把 `eqFadeTimer` 真正用起来（或在原生 MultimodalEQ / Convolver 入口做 gain ramp），消除咔哒声。
2. **预设导入 / 导出**：发烧友常把自己的 EQ 曲线分享给别人，当前只能靠手调。
3. **A/B 对比**：长按某按钮瞬间 bypass 整个 JamesDSP，松开恢复——这是调 EQ 时最常用的需求。
4. **频谱 / 电平表**：页面底部诊断行可加一个简易峰值表，让用户看大增益组合有没有顶到限幅器。
5. **删除 DDC 自定义项后的索引漂移**已在 `soundEffect.ts:351-357` 处理，但删完之后没有"已删除"的 toast 反馈，建议补一个轻提示。
6. **导入 DDC 时的文件选择器只允许 .wav**（`soundEffectSetting.tsx:141`），但没在选择器层禁止 8-bit / 非 48k；建议在 `importDdcPreset` 里读 WAV 头校验后再决定是否入库。

## 5. 未验证项（诚实列出）

- 未在真机 / 模拟器上安装运行，**所有"听感类"结论**（是否真的爆音、限幅器泵感是否可闻、44.1k/48k 混响错位是否一耳朵可辨）均为代码推断，未实听。
- `JamesDSPProcessor.queueInput`（`:62-82`）里"outputBuffer 仍有剩余就 return、不消费 input"的写法是否与 ExoPlayer AudioSink 的消费契约完全兼容，未跑实测；理论上 ExoPlayer 会先 `getOutput` 再 `queueInput`，但极端分包顺序下是否有丢帧/死锁风险未验证。
- 蓝牙 A2DP / 官方 offload 路径下 `JamesDSPProcessor` 是否被 ExoPlayer 整体跳过（offload 不走 AudioProcessor）未在真机确认；若被跳过，则蓝牙听歌时所有 DSP 静默失效——这一点代码里没有显式处理，**建议真机验证**。
- `assets/ir/ddc/*.wav` 的内容是否真是对应耳机的 AutoEQ 最小相位补偿曲线（5 个文件大小都是 19244 字节、MD5 不同，但波形本身是否有实际补偿量）未做频响分析，只验证了存在性与文件头。
- 旧的 `SoundEffectModule`（`android.media.audiofx` 那一套 Equalizer/BassBoost/Virtualizer）与 JamesDSP 是否存在双重叠加：`PROJECT_HANDOVER.md` 写明旧系统"已废弃仅保留注册"，但 `src/core/soundEffect.ts` 里 `applyBassBoost / applyVirtualizer / applyLoudnessEnhancer` 等函数仍在写配置并调用旧模块——页面 UI 已不再暴露这些开关，但若历史配置里残留值，`applyAllConfig` 不会去碰它们，是否会与新 JamesDSP 路径同时生效未验证。
