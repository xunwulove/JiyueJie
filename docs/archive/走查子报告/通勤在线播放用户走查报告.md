# 极悦界（Jiyuejie）通勤在线播放用户走查报告

- 走查版本：0.6.2.15（源码静态走查，未真机运行）
- 走查视角：日常通勤（地铁/公交）、移动流量在线听歌、频繁切歌、信号差环境
- 走查方式：只读源码通读，不修改、不构建、不运行
- 说明：本环境无 adb/模拟器/真机，所有结论均来自源码静态阅读；凡涉及实际界面表现的均标注"未验证"。

---

## 1. 画像与使用场景

- 早高峰地铁/公交通勤，单程 30–60 分钟，移动数据在线播放，频繁进出信号盲区（隧道、地下站台）。
- 高频操作：切歌（下一首/上一首）、播放暂停、进度条微调、切歌看歌词。
- 核心诉求（按优先级）：
  1. 播放不中断——隧道短暂断网后能续上，而不是直接跳到下一首；
  2. 切歌快——点下一首立刻有响应，切完不残留上一首的声音/歌词；
  3. 通知栏 + 蓝牙耳机可控——播放暂停、上下曲，不用掏手机；
  4. 进度不丢——杀进程/锁屏后再打开能续播。
- 易错点：移动网络播放开关、音源失效 403、切歌竞态、最后一首切下一首、断网恢复。

## 4. 可优化建议

### P1 功能性
- **失败重试一次再切歌**（trackPlayer/index.ts:1048）：PlaybackError 后先延迟 2–3s 重试当前曲一次（隧道抖动自愈窗口），仍失败再 skipToNext；并对"连续 N 首失败"计数（如连续 3 首失败即停止并 toast"网络不可用"），避免无声连跳整队。
- **音源解析异常兜底**（trackPlayer/index.ts:674）：catch 中未识别 message 的分支应统一走 handlePlayFail()（或至少 showToast"播放失败"），而不是静默吞掉——这是 P1-1 的根因。
- **网络恢复自动续播**（src/utils/network.ts 仅监听状态）：Network 类只更新 `_state`，没有"Offline→Connected 时若当前处于错误/暂停则自动重试"的钩子。建议在 NetInfo 回调里检测播放状态并触发一次重试。

### P2 体验/细节
- changeQuality 失败静默 return false（trackPlayer/index.ts:789-792）：切换音质失败时无 toast，用户以为已切到高品质。建议失败时提示"当前音质不可用"。
- 蓝牙断开行为：bootstrap.ts:194-198 `alwaysPauseOnInterruption: true` + service/index.ts:23 默认不打断 duck——蓝牙耳机断开导致的焦点丢失被默认忽略，音乐可能突然从手机扬声器外放。建议在设置里给"蓝牙断开自动暂停"开关，或文档说明默认行为。
- 通知栏 compactCapabilities（bootstrap.ts:199-200）未含 SeekTo，折叠通知里不能拖动进度；锁屏大通知有 SeekTo（notificationCapabilities）。折叠态是否加 SeekTo 可按需求权衡。
- 迷你条（musicBar/index.tsx）补回点击进详情页的入口（当前被注释）。
- 歌词页 lyric/index.tsx:148 判断 `currentLrcItem?.index === -1`，但 lrcParser.getPosition 从不返回 index=-1 的项（返回 null），该分支为死代码，可清理。
