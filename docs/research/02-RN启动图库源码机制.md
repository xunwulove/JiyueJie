# RN 启动图库源码机制调研：expo-splash-screen 与 react-native-splash-screen

> 调研目的：从源码层面拆解两个主流 RN 启动图库的 Android 实现，对照本项目（极悦界，RN 0.76.5 fork）"原生 windowBackground layer-list + values-v31 系统 splash 属性 + expo-splash-screen（preventAutoHideAsync/hideAsync）"三端衔接方案，判断是否齐全、是否有坑。
>
> 调研方式：直接从 GitHub 拉取单个源文件（raw.githubusercontent.com），未 clone 大仓库。所有结论均附文件路径 + 代码摘录 + 来源 URL。
>
> 调研时间：2026-10-14。分支：expo 取 `main`，crazycodeboy 取 `master`（v3.3.0）。

---

## 0. 结论速览（先看这个）

| 维度 | expo-splash-screen（现代方案） | react-native-splash-screen（crazycodeboy，老方案） |
|---|---|---|
| 底层依赖 | **委托给 `androidx.core:core-splashscreen`** 的 `SplashScreen.installSplashScreen()` | **自己 new 一个 `Dialog`** 盖在 Activity 上 |
| 是否注入 windowBackground | 插件**不直接写** `windowBackground`，而是用 `Theme.SplashScreen` 父主题 + 系统 splash 属性 | **完全不碰 windowBackground**；靠 `windowIsTranslucent=true` 让窗口透明，再用 Dialog 盖住 |
| Android 12+ 适配 | **完整适配**：`windowSplashScreenBackground` / `windowSplashScreenAnimatedIcon` / `postSplashScreenTheme` / `windowSplashScreenBehavior` | **基本无适配**：老库，API 31+ 系统 splash 会先于它弹出，存在双启动屏/闪烁风险 |
| 隐藏机制 | OnPreDraw 拦截内容绘制 + ReactMarker `CONTENT_APPEARED` 自动隐藏 + JS 手动 hide | 直接 `dialog.dismiss()` |
| 图片多屏 | 插件按 mdpi~xxxhdpi 五档位图 + 288dp 画布合成 | 手动放 `drawable-*/launch_screen.png`，靠 Android 自动缩放 |

**一句话**：expo-splash-screen 现代分支就是 AndroidX 系统 splash 的封装；crazycodeboy 是 Dialog 遮罩 hack，不具备系统 splash 能力。本项目采用前者思路是对的。

## Q1：windowBackground 注入机制

### Q1.1 expo-splash-screen：不直接写 windowBackground，走"主题切换"模式

expo 官方 manual 文档（README）给的"裸用"示例确实是写 `windowBackground`：

```xml
<!-- res/values/styles.xml -->
<style name="AppTheme" parent="Theme.AppCompat.Light.NoActionBar">
  <item name="android:windowBackground">@drawable/splashscreen</item>
</style>
```

对应的 drawable 是一个 layer-list：

```xml
<!-- res/drawable/splashscreen.xml -->
<layer-list xmlns:android="http://schemas.android.com/apk/res/android">
  <item android:drawable="@color/splashscreen_background" />
  <!-- NATIVE 模式才加这一项 -->
  <item>
    <bitmap android:gravity="center" android:src="@drawable/splashscreen_image" />
  </item>
</layer-list>
```

来源：
- README manual 配置段：https://github.com/expo/expo/blob/main/packages/expo-splash-screen/README.md
- 插件实际生成 layer-list 的代码：https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashDrawables.ts

但 **插件（config plugin）真正落地到新建项目时**，走的是另一套——它生成一个独立的启动主题 `Theme.App.SplashScreen`，父主题是 AndroidX 提供的 `Theme.SplashScreen`，并往 MainActivity 注入注册代码：

```ts
// withAndroidSplashStyles.ts（plugin/src/）
const styleResourceGroup = { name: 'Theme.App.SplashScreen', parent: 'Theme.SplashScreen' };

const item = [
  { $: { name: 'windowSplashScreenBackground' }, _: '@color/splashscreen_background' },
  { $: { name: 'windowSplashScreenAnimatedIcon' }, _: '@drawable/splashscreen_logo' },
  { $: { name: 'postSplashScreenTheme' }, _: '@style/AppTheme' },
  { $: { name: 'android:windowSplashScreenBehavior' }, _: 'icon_preferred' },
];
```

```ts
// withAndroidSplashMainActivity.ts
// 1) 把 MainActivity 里的 setTheme(R.style.AppTheme) 注释掉
// 2) 在 super.onCreate(null) 之前插入：
//    SplashScreenManager.registerOnActivity(this)
```

也就是说，**MainActivity 的 android:theme 在 Manifest 里指向 `Theme.App.SplashScreen`**（而不是 `AppTheme`），系统用这个主题画启动屏，启动结束后由 `postSplashScreenTheme` 切回 `AppTheme`。`windowBackground` 这件事被 AndroidX 的 `Theme.SplashScreen` 父主题在内部接管（API<31 兼容路径），expo 插件自己不写 `windowBackground`。

来源：
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashStyles.ts
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashMainActivity.ts

### Q1.2 crazycodeboy：Dialog 遮罩，根本不注入 windowBackground

原生实现核心：

```java
// SplashScreen.java（org.devio.rn.splashscreen 包）
public static void show(final Activity activity, final int themeResId, final boolean fullScreen) {
    activity.runOnUiThread(() -> {
        if (!activity.isFinishing()) {
            mSplashDialog = new Dialog(activity, themeResId);  // 新建 Dialog
            mSplashDialog.setContentView(R.layout.launch_screen); // 装载用户写的 launch_screen.xml
            mSplashDialog.setCancelable(false);
            mSplashDialog.show();
        }
    });
}

public static void hide(Activity activity) {
    _activity.runOnUiThread(() -> {
        if (mSplashDialog != null && mSplashDialog.isShowing()) {
            if (!_activity.isFinishing() && !isDestroyed) {
                mSplashDialog.dismiss();
            }
            mSplashDialog = null;
        }
    });
}
```

库自带的 Dialog 主题（注意：**不是** windowBackground，而是 Dialog 窗口的退出动画）：

```xml
<!-- android/src/main/res/values/styles.xml（库自带） -->
<style name="SplashScreen_SplashAnimation">
  <item name="android:windowExitAnimation">@android:anim/fade_out</item>
</style>
<style name="SplashScreen_SplashTheme" parent="Theme.AppCompat.NoActionBar">
  <item name="android:windowAnimationStyle">@style/SplashScreen_SplashAnimation</item>
</style>
```

用户侧 AppTheme 要做的关键改动是**透明窗口**（让 Dialog 弹出来之前不闪白）：

```xml
<!-- 用户 app 的 styles.xml（README / examples） -->
<style name="AppTheme" parent="Theme.AppCompat.Light.NoActionBar">
  <item name="android:windowIsTranslucent">true</item>
</style>
```

用户自己写的 `launch_screen.xml`（examples 里的真实样例）：

```xml
<!-- examples/android/app/src/main/res/layout/launch_screen.xml -->
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent" android:layout_height="match_parent"
    android:background="@drawable/launch_screen" android:orientation="vertical">
</LinearLayout>
```

可见它的"启动图"本质是 **Dialog 背景 = @drawable/launch_screen**，而不是 Activity 的 windowBackground。

来源：
- https://github.com/crazycodeboy/react-native-splash-screen/blob/master/android/src/main/java/org/devio/rn/splashscreen/SplashScreen.java
- https://github.com/crazycodeboy/react-native-splash-screen/blob/master/android/src/main/res/values/styles.xml
- https://github.com/crazycodeboy/react-native-splash-screen/blob/master/examples/android/app/src/main/res/layout/launch_screen.xml
- https://github.com/crazycodeboy/react-native-splash-screen/blob/master/README.md

## Q2：Android 12+（API 31+）系统 splash 强制时代的适配

### Q2.1 expo-splash-screen：完整走系统 splash，且显式处理了 postSplashScreenTheme

native 入口直接调用 AndroidX 兼容库：

```kotlin
// SplashScreenManager.kt
object SplashScreenManager {
    private lateinit var splashScreen: SplashScreen

    fun registerOnActivity(mainActivity: Activity) {
        splashScreen = mainActivity.installSplashScreen()  // ← androidx.core.splashscreen.SplashScreen
        ReactMarker.addListener(contentAppearedListener)
        // ... OnPreDraw 拦截
        configureSplashScreen()
    }
}
```

插件写入的系统 splash 属性（见 Q1.1 摘录）：

- `windowSplashScreenBackground` = `@color/splashscreen_background`
- `windowSplashScreenAnimatedIcon` = `@drawable/splashscreen_logo`
- `postSplashScreenTheme` = `@style/AppTheme`  ← **显式处理了**
- `android:windowSplashScreenBehavior` = `icon_preferred`

**关于 `iconBackgroundColor`（即 `windowSplashScreenIconBackgroundColor`）：源码里没有写。** 在 `withAndroidSplashStyles.ts` 的 item 列表中只有上述 4 项，没有 `windowSplashScreenIconBackgroundColor`。也就是说 expo 插件**不设置**图标背景色（默认透明，图标直接落在 splash 背景上）。如果产品要求图标有一个圆形底色，需要自己补这一项。

**API<31 兼容**：AndroidX `core-splashscreen` 的 `Theme.SplashScreen` 父主题在低版本上自行把上述属性翻译成可渲染的 splash 视图；expo 自己不写版本分支。退出动画在 native 里统一处理：

```kotlin
// SplashScreenManager.kt
splashScreen.setOnExitAnimationListener { splashScreenViewProvider ->
    val splashScreenView = splashScreenViewProvider.view
    splashScreenView.animate()
        .setDuration(duration)          // 默认 400ms
        .alpha(0.0f)
        .setInterpolator(AccelerateInterpolator())
        .withEndAction {
            if (Build.VERSION.SDK_INT < Build.VERSION_CODES.S) {
                splashScreenViewProvider.remove()
            } else {
                // Avoid calling applyThemesSystemBarAppearance
                (splashScreenView as SplashScreenView).remove()
            }
        }.start()
}
```

- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/android/src/main/java/expo/modules/splashscreen/SplashScreenManager.kt
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashStyles.ts

### Q2.2 crazycodeboy：基本无系统 splash 适配

- 库本身不读 `windowSplashScreen*` 任何属性，也不依赖 `core-splashscreen`。
- 它的 `SplashScreen.show()` 是在 `MainActivity.onCreate` 里、`super.onCreate()` **之前**手动弹 Dialog。
- 在 API 31+ 设备上，系统会**先**用 Manifest 里 Activity 主题的 `windowSplashScreenBackground`（或 fallback 到 windowBackground）画一个系统 splash，等 Activity 起来后 crazycodeboy 的 Dialog 再盖上去——**两段式启动屏**，极易出现"系统闪一下 → Dialog 再闪一下"的跳变。
- 库里唯一的新 API 兼容是 API 28 刘海屏：

```java
// SplashScreen.java
private static void setActivityAndroidP(Dialog dialog) {
    if (Build.VERSION.SDK_INT >= 28) {
        dialog.getWindow().addFlags(WindowManager.LayoutParams.FLAG_LAYOUT_NO_LIMITS);
        lp.layoutInDisplayCutoutMode = WindowManager.LayoutParams.LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES;
    }
}
```

来源：https://github.com/crazycodeboy/react-native-splash-screen/blob/master/android/src/main/java/org/devio/rn/splashscreen/SplashScreen.java

## Q3：图片资源多屏适配（尺寸 / 密度 / 9-patch / 缩放模式）

### Q3.1 expo-splash-screen：按 288dp 画布 + 五档密度自动合成

插件把用户给的一张 logo 图，自动放到不同密度目录，并合成在一个**正方形透明画布**上：

```ts
// withAndroidSplashImages.ts
const DRAWABLES_CONFIGS = {
  mdpi:    { multiplier: 1,   path: './res/drawable-mdpi/splashscreen_logo.png' },
  hdpi:    { multiplier: 1.5, path: './res/drawable-hdpi/splashscreen_logo.png' },
  xhdpi:   { multiplier: 2,   path: './res/drawable-xhdpi/splashscreen_logo.png' },
  xxhdpi:  { multiplier: 3,   path: './res/drawable-xxhdpi/splashscreen_logo.png' },
  xxxhdpi: { multiplier: 4,   path: './res/drawable-xxxhdpi/splashscreen_logo.png' },
};

// 每档合成逻辑：
const size = imageWidth * multiplier;        // imageWidth 默认 100（dp）
const canvasSize = 288 * multiplier;          // ← Android 12 splash 图标总窗口 288dp
// foreground 居中贴到 transparent 288*multiplier 画布上
compositeImagesAsync({ background, foreground, x: (canvasSize-size)/2, y: (canvasSize-size)/2 });
```

关键规格：
- **画布 288dp**：这是 Android 12 系统 splash 给图标的总可视窗口（图标本体建议 ≤240dp，外加 48dp 安全边距）。expo 直接按 288dp 出图，保证图标不被系统 mask 裁切。
- **logo 宽度默认 100dp**（`imageWidth` 可配），对应 mdpi 100px、hdpi 150px、xhdpi 200px、xxhdpi 300px、xxxhdpi 400px，居中放在 288dp 透明画布上。
- **不使用 9-patch**：用的是 `<bitmap android:gravity="center">` 居中放置，而不是拉伸。
- **深色模式**：每个密度目录都有对应 `drawable-night-*/` 变体（mdpi~xxxhdpi 全档位）。
- resizeMode 三档：`contain`（默认）/ `cover` / `native`，通过 `res/values/strings.xml` 的 `expo_splash_screen_resize_mode` 字符串传给 native。

默认参数（getAndroidSplashConfig.ts）：

```ts
{
  imageWidth: 100,
  resizeMode: 'contain',
  backgroundColor: '#ffffff',
  // mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi 默认都回退到 root.image
}
```

- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashImages.ts
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/getAndroidSplashConfig.ts
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/plugin/src/withAndroidSplashStrings.ts

## Q4：隐藏时机——如何保证"JS 就绪才隐藏"

### Q4.1 expo-splash-screen：双保险（自动 + 手动），但**无超时兜底**

JS API 层：

```kotlin
// SplashScreenModule.kt
AsyncFunction<Boolean>("preventAutoHideAsync") {
    userControlledAutoHideEnabled = true
    SplashScreenManager.preventAutoHideCalled = true
    return@AsyncFunction true
}
AsyncFunction("hideAsync") { SplashScreenManager.hide() }
Function("hide") { SplashScreenManager.hide() }
```

native 层两条隐藏路径：

```kotlin
// SplashScreenManager.kt
private var keepSplashScreenOnScreen = true
var preventAutoHideCalled: Boolean = false

// 路径 A：RN 内容首次挂载（ReactMarker CONTENT_APPEARED）自动隐藏
private val contentAppearedListener = ReactMarker.MarkerListener { name, _, _ ->
    if (name == ReactMarkerConstants.CONTENT_APPEARED) {
        if (!preventAutoHideCalled) {   // ← 只有没手动 prevent 过才自动隐藏
            hide()
        }
    }
}

// 路径 B：OnPreDraw 拦截 contentView 绘制，直到 keepSplashScreenOnScreen=false
val observer = contentView.viewTreeObserver
observer.addOnPreDrawListener(object : OnPreDrawListener {
    override fun onPreDraw(): Boolean {
        if (keepSplashScreenOnScreen) return false  // 拦着不画
        contentView.viewTreeObserver.removeOnPreDrawListener(this)
        return true
    }
})

fun hide() { keepSplashScreenOnScreen = false }
```

机制解读：
1. **默认行为**：不调 `preventAutoHideAsync` 时，RN 首屏内容一挂载（`CONTENT_APPEARED` marker）就自动淡出。
2. **手动模式**：调了 `preventAutoHideAsync()` 后，`CONTENT_APPEARED` 不再触发隐藏，必须等 JS 调 `hideAsync()` → `hide()` 把 `keepSplashScreenOnScreen` 置 false，OnPreDraw 才放行。
3. **OnPreDraw 是兜底**：因为 `splashScreen.setKeepOnScreenCondition()` 在 API<33 不生效，所以 expo 自己用 OnPreDraw 拦 contentView 绘制，确保系统 splash 退出动画开始前内容还没露出来。
4. **没有超时**：源码里**没有任何 setTimeout / postDelayed 兜底**。如果 JS 调了 `preventAutoHideAsync()` 但 bundle 加载失败 / 崩溃 / 漏调 `hideAsync()`，启动屏会一直挂着。这是需要在业务侧自己加超时的点。

与系统 splash 结束时机的关系：API 31+ 上，系统 splash 先由系统画出来，`installSplashScreen()` 接管后通过 `setKeepOnScreenCondition`（高版本）或 OnPreDraw（低版本）把它"按住"，直到 JS 就绪再播 400ms alpha 淡出。

来源：
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/android/src/main/java/expo/modules/splashscreen/SplashScreenModule.kt
- https://github.com/expo/expo/blob/main/packages/expo-splash-screen/android/src/main/java/expo/modules/splashscreen/SplashScreenManager.kt

### Q4.2 crazycodeboy：完全由 JS 调用 hide() 决定

```java
// SplashScreenModule.java
@ReactMethod public void hide() { SplashScreen.hide(getCurrentActivity()); }
```

- 没有自动隐藏：JS 不调 `SplashScreen.hide()`，Dialog 就一直显示。
- 也没有超时兜底。

## Q5：对照本项目方案的可借鉴点与坑

本项目方案：**原生 windowBackground（layer-list）+ values-v31 系统 splash 属性 + expo-splash-screen JS 侧 preventAutoHideAsync/hideAsync**。逐条对照：

### Q5.1 可直接借鉴的做法

1. **主题切换模式（postSplashScreenTheme）**：expo 插件把 Activity 主题指向 `Theme.App.SplashScreen`，启动结束切回 `AppTheme`。本项目在 `values-v31` 里只写系统 splash 属性是对的，但要确认：
   - Manifest 里 MainActivity 的 `android:theme` 是否指向一个**同时带 windowBackground（API<31）和 windowSplashScreenBackground（API31+）的主题**；
   - 是否设了 `postSplashScreenTheme` 指向真正的运行时主题。**漏写 postSplashScreenTheme 会导致启动结束后主题不切换/状态栏样式异常**——这是 expo 特意处理的一项，建议本项目照抄。
2. **图标画布 288dp**：如果本项目用系统 splash 图标，出图应按 288dp 画布（图标本体 ≤240dp），避免被系统 mask 裁切。expo 的 `canvasSize = 288 * multiplier` 就是这个数。
3. **OnPreDraw 拦截思路**：如果发现 API<33 设备上"系统 splash 一退出就闪白屏/内容提前露出"，说明缺了内容绘制拦截。expo 的做法是在 `android.R.id.content` 上挂 OnPreDraw，return false 直到 keepOnScreen=false。本项目若遇到此现象可照此抄。
4. **退出动画统一 400ms alpha 淡出**：避免硬切。

### Q5.2 需要警惕的坑

1. **`windowSplashScreenIconBackgroundColor` expo 默认不设**。本项目若要求图标有圆形底色，需自己在 `values-v31/styles.xml` 补 `<item name="windowSplashScreenIconBackgroundColor">...</item>`，expo 不会帮你写。
2. **expo 无超时兜底**：`preventAutoHideAsync()` 之后如果 JS bundle 加载失败，启动屏会永久停留。**建议业务侧自己加一个超时（例如 3~5s）兜底 hideAsync()**，这是两个库都没做、必须自己补的。
3. **crazycodeboy 的 Dialog 方案在 API 31+ 会双启动屏**：本项目**不要**混用 crazycodeboy 风格的 Dialog 遮罩，否则系统 splash + Dialog 两段闪烁。
4. **windowBackground 与系统 splash 属性的分工**：
   - API<31：靠 `windowBackground`（layer-list：纯色底 + bitmap 居中）。
   - API31+：靠 `windowSplashScreenBackground` + `windowSplashScreenAnimatedIcon`。
   - 本项目"values-v31 写系统属性、values 写 windowBackground layer-list"的分层是正确的；要确认两套里**背景色值一致**，否则版本切换瞬间会变色。
5. **深色模式**：expo 用 `values-night/` + `drawable-night-*/` 全档位。本项目若支持深色模式，需同时给 windowBackground 一套 night 变体，否则深色模式下启动屏背景色不跟随。
6. **`windowIsTranslucent` 不要乱加**：那是 crazycodeboy Dialog 方案才需要的。本项目用系统 splash 时，加 `windowIsTranslucent=true` 反而会导致启动屏透明/不可控，应去掉。

### Q5.3 本项目方案完备性核对清单

- [ ] MainActivity 主题在 API31+ 下含 `windowSplashScreenBackground`、`windowSplashScreenAnimatedIcon`、`postSplashScreenTheme`。
- [ ] API<31 下含 `windowBackground`（layer-list：纯色 + 居中 bitmap）。
- [ ] 两套背景色一致；深色模式有 night 变体。
- [ ] 图标出图按 288dp 画布、五档密度。
- [ ] JS 侧 `preventAutoHideAsync()` + 超时兜底 + `hideAsync()`。
- [ ] 退出有淡出动画，不硬切。
