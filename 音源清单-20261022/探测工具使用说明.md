# 音源探测工具使用说明（probe_plugin.js v3）

> 定位：**AI 初筛 → 本脚本真实探测 → 人工复核 → 一键发布**工作流的配套工具。脚本负责真实、可复核的验证，结果交给你在 App 内实际点播确认。
> 脚本位置：`E:\Temp\Deepseek\source-check\probe_plugin.js`（v2 备份 `probe_plugin.v2.bak.js`，v1 备份 `probe_plugin.v1.bak.js`）

## 一、能力总览

| 能力 | 说明 | 触发参数 |
|---|---|---|
| 真实搜索验证 | 加载插件 JS → 沙箱真实调用搜索/榜单接口 → 判定能否搜到歌 | 默认 |
| 深度播放验证 | 搜到歌后解析真实播放地址并探测可访问性，**能播才判有效** | `--play=N`（默认 3） |
| 假阳性拦截 | 200 但返回 HTML/JSON 错误页的地址判不可播（Content-Type 必须为音频类） | 默认（P0） |
| 多关键词搜索 | 批量验证时任一关键词命中即可搜，覆盖单词盲区 | `--keywords=词1,词2`（P0） |
| 一键发布清单 | 从 A 档自动生成 gitee 严格格式（name/version/url）可发布 plugins.json | `--publish=路径`（P0） |
| 歌单能力验证 | 验证推荐歌单/用户歌单/榜单接口能否拉到非空列表（对应 App 推荐歌单功能） | `--sheets`（P1） |
| 档位细分 + 人工复核清单 | B 档细分为 B1（取不到地址）/B2（探测失败），报表单列"待人工复核清单" | 默认（P1） |
| 插件源码缓存 | 按 URL 哈希缓存插件源码，监控多轮只重下变化源 | `--cacheDir=目录`（P1） |
| AI 候选入口 | 直接探测 AI 产出的候选文件，不污染正式清单 | `--from=ai.json`（P1） |
| 登录类源标记 | 检测插件含 login/verifyToken 接口并标注"需登录" | 默认（P1） |
| 自动报表 | 一键产出可发布的分档 Markdown 报表（含复核清单区） | `--report[=路径]` |
| 定时监控失效 | 周期重测，与上轮对比输出"新增失效/恢复/升级"变化报告 | `--interval=秒`（可选 `--rounds=N`） |

## 二、常用命令

```bash
cd E:\Temp\Deepseek\source-check

# 1. 单源深度验证（含播放验证、歌单验证、登录标记）
node probe_plugin.js "https://.../plugin.js" "周杰伦" --play=3 --sheets

# 2. AI 初筛 → 真实探测 → 一键发布（推荐工作流）
node probe_plugin.js --from=ai-candidates.json --keywords=周杰伦,林俊杰 --play=3 --sheets --report=报表.md --publish=plugins-release.json

# 3. 全量验证 + 报表 + 发布清单（--cacheDir 加速多轮）
node probe_plugin.js --file plugins.json --keywords=周杰伦 --play=3 --report=报表.md --publish=plugins-release.json --cacheDir=cache

# 4. 定时监控（每 600 秒一轮，输出变化报告；自动启用缓存；Ctrl+C 停止）
node probe_plugin.js --file plugins.json "周杰伦" --interval=600 --report

# 5. 监控只跑 3 轮就退出
node probe_plugin.js --file plugins.json "周杰伦" --interval=600 --rounds=3
```

常用参数：`--concurrency=并发数` `--retry=重试次数` `--play=N 播放验证歌曲数(0=关闭)` `--qualities=standard,high,low 音质尝试顺序` `--playTimeout=毫秒 单地址探测超时` `--sheets[=N] 歌单验证条数` `--keywords=词1,词2 多关键词任一命中` `--roundDir=目录 监控存档目录` `--cacheDir=目录 插件源码缓存`

### AI 候选文件格式（--from 支持三种）

```json
{ "candidates": [ { "name": "源名", "url": "https://.../plugin.js", "note": "AI 备注", "source_site": "来源站" } ] }
{ "plugins": [ { "name": "...", "url": "..." } ] }
[ { "name": "...", "url": "..." } ]
```

## 三、档位判定（报表核心）

| 档位 | 含义 | 判定依据 |
|---|---|---|
| **A** | 真实可搜 + 可播 | 搜索返回歌曲，且前 N 首中 ≥1 首解析出播放地址并探测 HTTP 200/206 **且 Content-Type 为音频类** |
| **A1** | 可搜 + 防盗链嫌疑 | 解析到播放地址但探测 403——**需 App 内人工复核**，不能判死 |
| **B2** | 可搜 + 地址探测失败 | 取到播放地址但探测 4xx/5xx/超时/非音频 200——**需 App 内复核** |
| **B1** | 可搜但取不到地址 | 未解析到播放地址（可能需登录/参数/特定音质）——**需 App 内复核** |
| **B** | 可搜未验播 | 未开启播放验证（`--play=0`） |
| **C** | 仅可达未搜到 | 插件能下载加载，但搜索返回空（含间歇限流重试后仍空） |
| **X** | 失效 | 下载失败 / 加载失败 / 无搜索接口 |

报表自动单列 **"三、人工复核清单"** 区：A1/B2/B1 逐条列出搜索量、播放详情、复核要点，供你在 App 内勾选确认。

## 四、深度播放验证原理（为什么"真实有效"）

1. **取地址双协议**：优先歌自带 url → 标准协议 `getMusicUrl(item, quality)`（按音质顺序，拿到即停）→ 旧协议 `getMediaSource(item)`（腾讯系等，可能带 headers）。
2. **防盗链头保留**：插件返回的 headers（Referer 等）在探测时原样携带，避免"无头 403 误杀真实可播源"。
3. **轻量探测**：GET + `Range: bytes=0-2047` 只读首块即断开，不下载整首；跟随重定向。
4. **防假阳性（v3 新增）**：HTTP 200/206 但 Content-Type 为 `text/*` 或 `application/json`（登录页/错误页/CDN 兜底页常见）判不可播，记 `urlFake` 拦截数；`audio/*`、`application/octet-stream`、空类型放行（避免误杀真实音频流）。
5. **诚实标注**：解析失败/超时/无 URL 一律记原因不计可播；单次"接口返回空"自动重试（间歇限流常见）；`aborted`、内部超时也重试。403 单列 A1、探测失败单列 B2，**脚本判定 ≠ 播放器实际体验**（防盗链/临时签名/地区限制可能不一致），以 App 内听感为准。
6. **stdout 纯净（v3 新增）**：插件内 console 输出与脚本自身日志一律走 stderr，子进程 stdout 只有最终 JSON——批量模式不会被插件日志污染。

## 五、一键发布清单（--publish，v3 新增）

- 只收 **A 档** 进发布清单，A1/B1/B2 留给人工复核（复核通过可手动补入）。
- 输出严格 gitee 格式：顶层仅 `desc` + `plugins`；条目仅 `name/version/url` 三字段；缺 version 补 `1.0.0`；不添加任何其它字段。
- desc 注明实测日期、可播数量与关键词，可直接作为 gitee 音源仓库的 plugins.json 发布。

## 六、插件源码缓存（--cacheDir，v3 新增）

- 按 URL 的 SHA-1 哈希缓存插件源码（`.js`）与下载元信息（`.meta.json`：httpStatus/sizeBytes/时间戳）。
- 命中缓存不重新下载，HTTP 状态与大小从 meta 读取——监控多轮与重复验证显著提速。
- **监控模式自动启用缓存**（`<roundDir>/cache/`），无需手动指定。

## 七、监控变化报告（results/ 目录）

- 每轮结果存档 `results/round-<时间戳>.json`，基线 `results/last.json`（`--baseline` 可指定其它基线）。
- 变化项写入 `results/changes-<时间戳>.md`：**新增失效**（A→X / B→X 等）、**恢复可用**（X→A/B）、**升级可播**（B→A）、**可播→仅可搜**（A→B）、**新增音源**、**移除**。
- 音源按 URL 匹配，**URL 变动但名称相同视为同一音源**（监控关注"源是否失效"而非"链接是否变动"）。
- `--report` 在监控模式每轮额外产出分档报表。

## 九、已知边界

- 插件内嵌超时（如歌曲宝 5s）或服务端风控（403）会导致判 C/X，属真实状态。
- 大混淆插件（网易云/酷狗等 300KB+）加载慢，单源可能耗时 30s+，全量 50 源约 20~40 分钟（--cacheDir + --concurrency 可加速）。
- Windows 终端（PowerShell）直接 cat JSON 会显示乱码，属终端编码问题，文件本身是 UTF-8；用编辑器打开正常。
- 危险模块拦截：v3 起沙箱拦截插件对 fs/path/child_process/net/os/vm 等的 require（返回空对象），保护本机文件安全——极少数依赖这些模块的插件会因此无法完整运行（正常音源插件不受影响）。
